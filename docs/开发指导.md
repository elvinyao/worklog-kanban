# 开发指导

## 首次准备与网络选择

从仓库根目录执行下列命令，先启动 Docker Desktop、OrbStack 或 Docker daemon。宿主仅检查和编辑源码；安装、构建、测试、项目脚本通过 Docker runner。Docker 不可用时修复 Docker，不回退宿主执行，也不需要在宿主安装 Python、Node 或项目依赖。

| 网络 | 入口 | 设置 |
| --- | --- | --- |
| 直连默认 | `bash .agent/run.sh <命令>` | 构建/运行清空 HTTP(S)/ALL proxy，不需公司 CA |
| 宿主代理 + CA | `bash .agent/run-proxy.sh <命令>` | 读取大写/小写代理变量，大写优先；要求 PEM CA 文件 |

首次和日常都使用 `tools.sync_deps`：空 Python 卷自动从哈希锁安装开发依赖，再同步并记录锁指纹；Node 使用 `npm ci`。锁未变时跳过安装。失败不更新对应指纹，修复网络后可直接重试，无需手工安装 `pip-tools`。

直连首次准备与启动：

```bash
bash .agent/run.sh python -m tools.sync_deps
bash .agent/run.sh npm run build
bash .agent/run.sh python -m tools.dev
```

代理（export 只配置宿主环境）：

```bash
export HTTP_PROXY=http://127.0.0.1:7890
export HTTPS_PROXY=http://127.0.0.1:7890
export NO_PROXY=localhost,127.0.0.1,.localhost,.company.example
export WORKLOG_CA_CERT=/absolute/path/company-ca.crt
bash .agent/run-proxy.sh python -m tools.sync_deps
bash .agent/run-proxy.sh npm run build
bash .agent/run-proxy.sh python -m tools.dev
```

HTTPS_PROXY 通常也填 `http://`，通过 HTTP CONNECT 访问 HTTPS，以公司要求为准。代理 URL 中 loopback 主机转换为 `host.docker.internal`，Linux 添加 host-gateway。代理须允许 Docker 连接；Linux 仅监听宿主 127.0.0.1 通常不可达，需调整为 Docker 可达地址并限制访问范围。

NO_PROXY 保留原值并追加 localhost 与模拟域名；不要加入仍需经过代理的公司域名。ALL_PROXY 清空避免冲突。

`WORKLOG_CA_CERT` 为宿主信任环境导出的 PEM CA，绝对路径、不含私钥；不自动读取 macOS Keychain。构建通过 BuildKit secret 临时加载 CA，运行通过只读挂载加入系统证书，Python/pip、requests、Node/npm 使用合并信任包。建议提供一张签发 CA；多证书 PEM 需验证完整链导入结果。不关闭 HTTPS 校验。开发镜像不保留公司 CA，正式镜像不继承此配置。浏览器 CA 信任另行管理。

基础镜像拉取属于 Docker daemon / BuildKit 网络。如 Docker Hub 需代理/私有 CA，先配置 Docker Desktop/OrbStack/daemon/构建器；runner 变量不能修复此层拉取失败。CI 的 registry 与构建网络也需 Runner 管理员配置。

## 日常开发与浏览器调试

普通功能修改从 fake 环境开始：执行上面的 `npm run build` 和 `python -m tools.dev`，在一个开发容器内监督三个服务。访问 `http://board.localhost:4173`；Chrome / Edge 扩展管理页开启开发人员模式，加载仓库的 `dist/extension-dummy` 目录。在 `http://jira.localhost:4180/jira/__dummy/` 与 `http://mattermost.localhost:4181/__dummy/` 分别登录 Alice 或 Bob，再回看板开启“卡片预览”。共享编辑不依赖扩展，个人预览需要同一浏览器 profile 中的扩展和两个站点会话。

多身份测试使用独立浏览器 profile，普通标签页共享会话。数据库 `.tmp/worklog.sqlite3` 与生产卷分开；Ctrl+C 停止服务并保留共享数据，模拟会话需在重启后重新登录。

当前没有自动构建或热重载，修改后按下表操作；构建命令在另一个终端执行。

| 修改内容 | 让变更生效 |
| --- | --- |
| `src/web/`、页面样式或翻译 | `bash .agent/run.sh npm run build`，完成后刷新看板。 |
| `src/extension/`、`src/adapters/` 或扩展使用的契约 | 重新构建，在浏览器扩展管理页重新加载扩展，再刷新看板；核对扩展设置中的地址覆盖。 |
| `app/`、`dummy/`、`tools/` 的服务代码 | Ctrl+C 停止，再执行 `bash .agent/run.sh python -m tools.dev`；若也改了前端，先构建。 |
| 依赖锁 | 执行 `bash .agent/run.sh python -m tools.sync_deps` 后重启服务、重新构建。 |

启动服务时保留上面的独立命令形式。runner 通过直接的 `python -m tools.dev` 或 `python dist/production/run.py` 参数发布宿主端口；放进子 shell 的服务不会发布端口。检查、测试等复合命令使用 `bash .agent/run.sh sh -c 'npm run check && npm run test:unit'`。使用 `sh -c` 保留虚拟环境 PATH；当前镜像中的 `sh -lc` 会重置 PATH，误用未安装开发依赖的系统 Python。

三容器 fake 部署见[执行与部署](执行与部署.md#fake-环境显式选择)。只调试接入探针时依次执行 `bash .agent/run.sh npm run build:probe` 和 `bash .agent/run.sh python -m tools.dev --probe`，访问 `/probe/`；探针不进入生产包。

## 真实站点与生产包调试

需要验证公司接入时，用编辑器从 `config/production.example.json` 创建被忽略的 `config/company.local.json`，填写公开站点地址，不放凭据。完成首次依赖准备后：

```bash
bash .agent/run.sh npm run build:production -- --config config/company.local.json
bash .agent/run.sh python dist/production/run.py --config config/company.local.json --database data/real-debug.sqlite3
```

4173 映射至宿主 loopback，启动前停止占用该宿主端口的调试服务。浏览器必须经配置的 `boardOrigin` 访问，必要时经本地反向代理保留 Host。加载 `dist/production/extension`，登录真实 Jira/MM。代理环境将入口换为 `run-proxy.sh`。修改站点地址后需重建看板并核对扩展配置；设置页仅更改当前浏览器的覆盖值。

不要在服务使用 `dist/production` 时重新构建该目录。并行检查其他配置可增加 `--output .tmp/release-check`，生成独立生产包；已有输出必须是有效发布目录，重建会将旧包保留为相邻的 `.previous-*` 目录。实际公司网络、SSO、浏览器策略另按[公司接入检查单](公司接入检查单.md)手动验收，dummy 自动测试不能替代这些检查。

## 验证顺序与定向测试

首次依赖准备完成后，完整验证使用以下顺序。`npm run check` 包含 TypeScript、生成 API 漂移、Python 语法和架构边界检查，不包含单元或浏览器测试。

```bash
bash .agent/run.sh python -m tools.sync_deps
bash .agent/run.sh npm run check
bash .agent/run.sh npm run build
bash .agent/run.sh python -m pytest tests/backend -q
bash .agent/run.sh npm run test:unit
bash .agent/run.sh npm exec -- playwright install chromium
bash .agent/run.sh npm run test:e2e
```

构建必须先于完整后端和 E2E 测试：后端生产测试也会启动 dummy 看板。完整后端套件会下载并安装隔离的 Python 依赖，生产包通过 `--output` 构建至 pytest 临时目录，不覆盖 `dist/production`。E2E 仍读取当前开发构建，不要在其运行时重建 `dist/web` 或扩展。

Playwright 自动启动和停止测试服务，默认使用临时隔离数据库与浏览器 profile。每次 runner 调用的容器网络相互独立，E2E 不发布宿主端口，因此无需仅因宿主 4173/4180/4181 被占用而停止普通 fake 调试服务。首次使用或 Playwright 更新后安装 Chromium；测试输出在终端，产物在 `.tmp/`。不要将个人生产库设为测试数据库。

修改时先运行相关测试，再按影响范围扩大；以下文件名可替换为实际变更对应的用例：

```bash
bash .agent/run.sh python -m pytest tests/backend/test_api.py -q
bash .agent/run.sh npm run test:unit -- tests/frontend/preview.test.ts
bash .agent/run.sh npm run test:e2e -- tests/e2e/extension-settings.spec.ts
```

涉及 React 挂载/卸载、预览连接或监听器清理时，额外验证开发版 StrictMode。环境变量在容器内设置，不能只在宿主命令前赋值：

```bash
bash .agent/run.sh npm run build -- --mode lifecycle-test
bash .agent/run.sh sh -c 'WORKLOG_TEST_MODE=lifecycle-test npm run test:e2e -- tests/e2e/previews.spec.ts tests/e2e/probe.spec.ts'
```

## 按变更场景补齐检查

草稿恢复为每个编辑窗口显式启用：卡片、列、归档创建/恢复/重命名均可保存输入，刷新后重新打开对应窗口选择“恢复草稿”。卡片和归档成功保存、编辑窗口明确取消会清理当前副本；列管理保存单项后保留窗口中其他输入，关闭时清理；取消勾选仅停止持久保存，保留当前输入。记录在当前浏览器 origin 内保留七天，下次访问草稿功能时清理过期记录，最多 20 份；空间不足时提示复制输入，不覆盖其他草稿。页脚“本机草稿”可查看、复制或删除记录，包括原任务已归档/删除的情况。它不是服务端备份；清理站点数据会删除草稿，公用浏览器慎用。

保存结果不确定时，持久草稿包含原请求标识和提交版本；恢复后重试必须使用原参数，不能换请求 ID。列名冲突须显示原名称、远端名称、本地输入，明确核对后才覆盖。扩展消息 15 秒超时后恢复操作能力，迟到回复不能覆盖当前输入；原生站点授权弹窗继续等待用户决定。

CI 无论成功失败都尝试保留 `.tmp/ci-results/`，含 JUnit、检查日志、服务日志和失败页面截图/trace，保留七天；扩展持久浏览器 profile 也单独收集失败现场。只有已经运行的阶段才有对应报告。日志/截图仅用于合成测试数据，不得将生产数据库或真实会话注入测试。可本地复现报告生成：

```bash
bash .agent/run.sh sh -c 'WORKLOG_TEST_REPORTS=/workspace/.tmp/ci-results npm run test:e2e'
```

备份恢复场景与操作步骤见[执行与部署](执行与部署.md#更新停止备份与恢复)，后端定向测试为 `tests/backend/test_maintenance.py`，浏览器恢复测试为 `tests/e2e/local-drafts.spec.ts`。

| 场景 | 必要动作与验收重点 |
| --- | --- |
| API 或共享模型 | 以 `app/schemas.py` 和 `app/api.py` 为源，修改后运行 `bash .agent/run.sh npm run generate:api`，同时提交 `contracts/shared-api.openapi.json` 与 `src/generated/shared-api.d.ts`；补后端/契约测试，再运行 `npm run check`（通过 runner）。不要手改生成文件。 |
| 看板、样式、翻译 | 更新 `src/web/i18n/messages.ts` 对应中/英/日文本，检查键盘、焦点、窄屏及空状态；覆盖保存响应丢失、15 秒超时后重试、重复点击、冲突、未保存输入的 Esc/取消/导航/刷新保护；运行相关单元/E2E，UI 变更附合成数据截图。 |
| 扩展或外部读取 | 覆盖 Alice/Bob 隔离、登录失效、权限撤销、地址不匹配、网络失败、取消和重连；验证 Jira 评论预算超限提示、Mattermost 元信息超时降级、设置首次加载失败后重试。个人预览正文、头像及会话凭据不得进入共享 API、数据库、日志或持久存储。 |
| 数据库或归档 | 同时验证新库与 `tests/fixtures/board-v1.sql`、`board-v2.sql` 旧库迁移，覆盖失败回滚、重启、备份/恢复、创建幂等重试和现有数据保留。归档分页覆盖搜索切换、远端重命名/恢复、失败重试及返回列表缓存；仅使用合成测试库。 |
| 依赖 | 按下节更新输入与锁文件，重新同步并运行受影响测试；开发工具留在开发依赖中。 |
| 仅文档 | 对照现有代码核对命令、路径、链接和前提，运行只读 `git diff --check`；无需为文字修改重跑全部应用测试，明确哪些示例未实测。 |
| 镜像或部署 | 验证对应镜像/Compose 与扩展配置，覆盖健康检查、升级及数据恢复；GitLab CI 对 MR、默认分支和 tag 执行检查、单元、后端和 E2E，默认分支/tag 通过后才构建并发布生产镜像；不自动部署。 |

## 依赖与部署工具维护

修改 Python `.in` 后依次生成 runtime 和 dev 哈希锁，再同步；dev 输入使用 runtime 锁作约束：

```bash
bash .agent/run.sh python -m piptools compile --allow-unsafe --strip-extras --generate-hashes --output-file requirements/runtime.txt requirements/runtime.in
bash .agent/run.sh python -m piptools compile --allow-unsafe --strip-extras --generate-hashes --output-file requirements/dev.txt requirements/dev.in
bash .agent/run.sh python -m tools.sync_deps
```

提交有变化的 `.in` 和对应 `.txt`。Node 依赖通过 runner 中的 `npm install --save-exact 包名@版本` 更新，开发依赖加 `--save-dev`；一起提交 `package.json` 与 `package-lock.json`，然后再次同步依赖指纹。不要把测试依赖加入 runtime，也不要手工改锁文件以绕过同步检查。

升级 Python/Node 时同步检查 `.python-version`、`.nvmrc`、`pyproject.toml`、`package.json` engines、`.agent/run.sh`、`.agent/Dockerfile`、`.agent/images.lock` 及生产/旧部署 Dockerfile，确保版本与镜像 digest 一致；不要为绕过安装失败任意升级运行时。

runner 检测锁变化会要求同步。`.agent/run.sh app` 仅保留兼容转发，部署使用明确的 Compose 或 `docker.sh` 入口。

镜像和 Compose 本地验证使用 `bash .agent/run.sh docker <参数>`：此分支只在宿主调度 Docker，构建和应用代码仍在容器内执行，不安装开发依赖，也不应用 run-proxy 的网络转换；镜像构建的代理参数由 Docker/BuildKit 配置管理。

## 常见问题

| 现象 | 处理方式 |
| --- | --- |
| Docker CLI/daemon 不可用 | 启动或修复 Docker 后重试；禁止改用宿主 Python/npm。 |
| Python 开发依赖缺失 | 执行 `bash .agent/run.sh python -m tools.sync_deps`；确认依赖安装成功且没有使用会重置 PATH 的 `sh -lc`。 |
| `Changed/uninstalled dependency locks` | 单独执行 `bash .agent/run.sh python -m tools.sync_deps`；无需删除数据库或全部 Docker 卷。 |
| 页面缺失、旧界面或 `Build complete dummy board` | 完整执行 `npm run build`（通过 runner）后刷新；`build:probe` 不能替代完整看板构建。 |
| 服务显示 READY，但宿主无法访问 | 使用独立服务启动命令，核对 localhost 域名、端口与代理绕过设置。 |
| Chromium executable 不存在 | 经 runner 执行 `npm exec -- playwright install chromium`，再运行 E2E。 |
| 扩展未连接或地址不匹配 | 核对加载目录和站点权限，重新加载扩展并刷新页面；检查个人地址覆盖，必要时恢复部署默认。 |
| 能编辑卡片但没有个人预览 | 开启“卡片预览”，确认同一 profile 已登录两个源站；模拟服务重启后重新登录。 |
| 镜像拉取失败或证书错误 | 区分 Docker daemon/BuildKit、容器包下载和浏览器三层，按首次准备中的代理/CA 说明配置对应层。 |
