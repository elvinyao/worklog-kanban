# 统一 Docker 部署与数据运维

用户已授权将正式配置接入 docker.sh，并增加诊断、备份、恢复；沿用现有入口和 main 本地提交，不重复审批同一范围。无新增依赖；Python 3.13.15 / Node 24.21.0 不变。

- `start --config config/company.local.json [--port 4173] [--trusted-proxy CIDR]` 首次创建正式部署。之后 start/update/stop/remove/status/logs 沿用最后成功配置。默认无配置仍为现有 dummy。不同模式使用不同 `--project`，不默默把已有模拟数据切为正式环境。
- 配置规范化、生成 Compose 在工具容器内完成；主机 shell 只协调 Docker。正式构建明确用 BuildKit secret 传入公开站点配置，复用既有生产打包与严格入口。运行镜像不含 dummy/probe/Node。
- Compose 顶层 x-worklog 保存模式、规范化站点、本地端口、代理设置；与服务定义作为一个 JSON 原子保存。候选成功才替换，失败保留旧配置/镜像。外部 boardOrigin 与 loopback 发布端口分别配置。正式模式只运行 board。
- 默认项目保留 dist/extension-docker，其他项目导出至 dist/extensions/<project>。扩展仍需用户授权安装。
- `doctor` 只读检查 Docker/Compose、已部署配置、容器健康、SQLite 完整性和外键；不构建、不访问真实源站、不自动修复。无已部署状态/数据库时清晰提示未检查。
- `backup` 使用 SQLite backup API，备份在仓库 backups/<project>/<id>/，不进入 Git；manifest 含 schema、revision、project、站点、时间、镜像和 SHA256。`backups` 列表不输出任务正文。
- `restore <id> --yes` 只恢复本项目匹配站点的受支持备份。先复制并校验输入，停止 board 后持有应用同一锁，备份恢复前状态，处理旧 WAL/SHM，再在同卷原子替换。保持原有停止/运行状态；失败保留备份。旧 pre-v3 原始备份无 manifest，不冒充本命令备份。
- 端口固定绑定 127.0.0.1，正式 HTTPS/域名仍由公司代理提供。本任务没有真实公司地址，使用保留域名在隔离项目演练；不改动真实任务做恢复测试。
