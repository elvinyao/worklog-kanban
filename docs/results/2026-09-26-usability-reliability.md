# 易用性与可靠性改善验收

本轮按数据与输入保护、预览性能、开发流程的顺序完成八项改善。所有项目执行均通过 `.agent/run.sh`；测试只使用合成数据和临时数据库。

开始于 2026-09-26；最终复核于 2026-10-03。

## 变更与场景

| 项目 | 结果与回归场景 |
| --- | --- |
| 1. 创建幂等 | 新建卡片保存稳定 requestId，数据库与创建记录同事务提交；覆盖响应丢失、后续 429、并发请求、失败回滚、重启、归档及删列后的重放。旧客户端不带 requestId 仍兼容。 |
| 2. 请求超时 | 共享 API 的请求和响应体均限制 15 秒；超时释放保存状态并保留输入。手动同步替换挂起读取，旧响应不能覆盖新状态。 |
| 3. 草稿保护 | 卡片、列、归档创建/重命名/恢复覆盖 Esc、取消、关闭、后退、刷新和保存中保护。远端删列保留可复制的列名；恢复的旧响应不能覆盖远端新归档名称。归档/恢复的不确定重试持续保留原 requestId；重命名保留版本冲突核对。 |
| 4. 预览预算 | Mattermost 作者、频道、头像并行读取，共享 3 秒预算；Jira 评论扫描最多 5 秒/10 页，无法完整读取时保留摘要并明确提示。取消、登录失效、权限拒绝和限流继续上报。 |
| 5. 增量归档 | 下一页只请求一个 cursor，返回列表保留缓存与滚动位置。普通卡片编辑不重新拉取归档，archiveRevision 驱动归档变动刷新；42 条记录的三页加载仅三次请求。 |
| 6. 设置恢复 | 扩展首次读取失败提供“重试加载”；读取成功前禁用保存与重置，避免覆盖未读取的配置。 |
| 7. 依赖引导 | 空 Python venv 可直接运行 tools.sync_deps，按哈希锁安装 pip-tools 后同步；失败不更新锁标记，重试可恢复。 |
| 8. 测试与发布 | GitLab MR、默认分支、tag 先执行完整测试；默认分支/tag 通过后才发布。独立 CI 镜像不挂载源码、不带部署凭据。生产构建支持 --output，生产测试在 pytest 临时目录完成，不覆盖 dist/production。 |
