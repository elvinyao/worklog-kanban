# 手动确认步骤

配套：[实施计划](../../2026-09-19_worklog-kanban/対応計画.md)、[测试矩阵](テスト観点マトリックス.md)。
本文件定义步骤，不填写当前结果。执行时把日期、执行者、代码版本、浏览器版本、步骤 ID、实际结果和证据位置写入 `manual/run-NNN/実行結果.md`，由 README 链接。

M01–M10 是 dummy 验收。M11 仅为以后真实接入准备，不阻塞本次模拟版本。尚未实现的命令来自计划约定，不能在当前状态假定可运行。

## M01：启动与模拟标识（P0，Dummy 必需）

**前提：**计划已批准，T01/T02/T06 已实现，Docker 可用。

**执行者：**代理执行容器命令；有浏览器操作能力时由代理操作，否则由用户完成浏览器部分。

1. 执行 `bash .agent/run.sh python -m tools.sync_deps`，按已提交的 Python runtime/dev 哈希锁与 package-lock 安装并同步依赖指纹。核对 Python 3.13.15 / Node 24.21.0。锁文件首次生成的历史步骤另见运行说明；不要把生成锁作为普通安装步骤，也不要在单独 npm ci 后遗漏指纹同步。
2. T06 阶段执行 `bash .agent/run.sh npm run build:probe`，再执行 `bash .agent/run.sh python -m tools.dev --probe`；T09 以后执行 `bash .agent/run.sh npm run build`，再执行 `bash .agent/run.sh python -m tools.dev`。启动后的页面由 FastAPI 提供。
3. 浏览器打开 `http://board.localhost:4173`、`http://jira.localhost:4180/jira/__dummy/`、`http://mattermost.localhost:4181/__dummy/`。
4. 按运行说明在扩展管理页加载 `dist/extension-dummy/`。在两个浏览器 profile 都安装同一构建。
5. 确认三个站点显示模拟标识，端口只发布于 loopback，无需公司账号。

**预期：**均可达，扩展可连接，页面没有混淆真实接入与 dummy。DNS、Docker 或扩展安装失败要记录原环节，不修改系统设置来掩盖失败。

**证据：**启动结果和模拟页面截图；不得包含个人真实浏览器资料。

## M02：双身份与评论分页（P0，Dummy 必需）

**前提：**M01 通过；两个独立 profile A/B，不只是同一 profile 的两个窗口。

**执行者：**代理或用户。

1. A 在两个 dummy 控制页选择 Alice；B 分别选择 Bob，不输入密码或 Token。
2. 两个 profile 打开同一看板/接入验证页，读取 `DEMO-1` 及同一公开 Mattermost 消息。
3. 对照 fixture：最新评论按创建时间选出，A/B 的可见最新评论按预设不同；最近编辑的旧评论不能被当成最新评论。
4. 读取 `DEMO-2` 和 Alice 专属消息，B 只看到不可用提示与原链接。
5. 检查看板服务收到的请求中没有两个 dummy 的认证 Cookie；只记录“有/无”，不复制 Cookie 值。
6. 观察 dummy 请求计数，评论确实跨页；Mattermost 没有讨论串/附件/写操作。

**预期：**共享内容一致，个人预览不同。用户身份由模拟会话决定，浏览器请求没有通过参数替换身份。

**证据：**合成页面截图及脱敏计数；真实凭据不得进入开发者工具导出或记录。

## M03：无扩展与断开（P0，Dummy 必需）

**前提：**已有共享卡片；完整 UI 实现。

**执行者：**代理或用户。

1. 暂停一个 profile 的扩展后刷新看板。
2. 创建/编辑共享卡片和笔记，打开原始链接。
3. 重新启用扩展，再连接并读取预览；另测扩展 worker 重启后的恢复。

**预期：**共享功能始终可用；预览有明确连接提示，恢复后不会混入另一页面的预览。

**证据：**状态变化截图与操作描述。

## M04：错误、旧内容与刷新（P0，Dummy 必需）

**前提：**先成功读取预览；所有故障仅在 dummy 控制页设置。

**执行者：**代理或用户。

1. 设定会话过期，再手动刷新：确认旧预览被清除。
2. 重新模拟登录；分别设置模糊 404、200 HTML 登录页和畸形 JSON，再读取。
3. 成功读取后设置网络中断/超时，刷新：应保留旧内容、标旧并显示上次成功时间。
4. 设置 429 与短的 Retry-After，连续尝试刷新：重试窗口内无重复外部请求。
5. 设置向未允许站点的重定向：目标计数为零，不先访问再报错。
6. 设置无评论/无担当者及头像失败：验证空态与局部降级。

**预期：**不把模糊错误推断为资源存在，不把 HTML 当正文；没有高频轮询。普通 HTML 或无法分类的跳转可以显示一般读取失败，不能伪称已识别公司登录。

**证据：**合成故障状态及请求计数，不保存真实外部响应。

## M05：协作、列操作与草稿（P0，Dummy 必需）

**前提：**两个页面连接同一 dummy 看板。

**执行者：**代理或用户。

1. 新增无 Jira 卡片并写笔记；绑定、更换、解绑 Jira，增加并重排多条消息链接。
2. 新增、重命名、重排列；删除有卡片的列并指定迁移目标。尝试删除唯一剩余列。
3. A/B 同时编辑一张卡片：A 先保存，B 提交旧版本，应保留 B 草稿并显示冲突。
4. B 有草稿时让 A 修改卡片，再断开/重连 B 的共享连接：草稿仍保留。
5. 同时移动同一卡片或删除其目标列，检查没有丢卡片、重复位置和部分提交。
6. 关闭有未保存笔记的详情，分别测试继续编辑和明确放弃。

**预期：**共享数据同步；旧版本不能静默覆盖；冲突后不自动拿新版本号重试旧文本。

**证据：**只含合成共享内容的截图及冲突过程说明。

## M06：键盘、IME、鼠标与焦点（P0，Dummy 必需）

**前提：**至少两列有卡片、一列为空；目标浏览器支持扩展。

**执行者：**代理可验证可操作部分；系统 IME 场景由实际输入法用户补充。

1. 上下/左右选择；最左/最右不循环，空列可获得焦点。
2. Alt+左右移动到相邻列末尾，确认浏览器没有后退/前进。
3. Enter 打开、Esc 关闭；焦点返回原卡片。
4. 在笔记输入区操作方向键、Enter，并进行中文/日文组合输入，确认不会移动卡片。
5. 拖拽跨列及列内排序；制造一次版本冲突，检查布局与焦点恢复。
6. 聚焦卡片因列迁移改变位置时，确认仍有可见且合理的焦点。

**预期：**符合设计的全部快捷键和鼠标语义，输入法编辑不受干扰。

**证据：**操作记录；必要时录制仅含 dummy 的短视频。自动模拟 composition 事件不能替代实际 IME 结论。

## M07：Chrome/Edge 与显示安全（P0，Dummy 必需）

**前提：**M01–M06 的代表性 fixture 可用。

**执行者：**在实际可用的 Chrome、Edge 中由代理或用户操作。

1. 在两个浏览器记录版本，安装扩展并重复登录、读取、编辑、移动和刷新。
2. 检查卡片紧凑程度、长标题、两至三行评论摘录、详情滚动与错误提示。
3. 加载带脚本/事件属性/危险链接/远程图片的合成内容，确认无脚本执行或意外资源读取。
4. 验证安全 Markdown 基本格式和原始链接新标签打开。

**预期：**两个目标浏览器核心操作均可用。缺少某一浏览器时记录未执行，不以 Playwright Chromium 结果代替该项。

**证据：**浏览器版本和仅合成数据的截图。

## M08：重启与数据保留（P0，Dummy 必需）

**前提：**使用专用 dummy 数据目录，已有合成共享修改。

**执行者：**代理或用户。

1. 记录当前共享卡片、列顺序及笔记。
2. 在运行 tools.dev 的终端用 Ctrl+C 停止；重新执行 `bash .agent/run.sh python -m tools.dev`。
3. 重开页面，确认共享修改保留、默认列没有重复创建。
4. 重新登录模拟身份并加载预览，确认预览是重新读取所得。

**预期：**持久化只覆盖共享数据，重启不删除已有数据库，不恢复持久化的个人预览。

**证据：**前后共享状态和重新读取计数。

## M09：隔离与证据审查（P0，Dummy 必需）

**前提：**T12 自动隔离测试已有结果。

**执行者：**代理主查，用户可复查。

1. 检查 A 专属合成标记不在 B 页面、共享 API/校验错误、SQLite、SSE、应用日志中。
2. 检查 HTTP cache、CacheStorage、浏览器与扩展持久存储不含预览；重开页面或从历史恢复后，服务端应收到新的实际请求。临时测试 profile 不进入 Git。
3. 检查候选提交文件不含 Cookie、Token、HAR、storageState 或真实正文。
4. 失败重跑使用新 attempt，README 只指向正确的最新结果。

**预期：**没有通过证据或同步旁路泄漏个人预览；fixture 源文件与应用运行日志明确区分。

**证据：**结构化通过/失败记录和必要的合成测试输出。

## M10：生产边界与来源 IP（P0，Dummy 必需）

**前提：**生产构建入口已实现；不实际接入公司系统。

**执行者：**代理。

1. 执行 `bash .agent/run.sh npm run build:production -- --config config/missing.local.json`，确认因缺配置明确失败；不创建该缺失文件。
2. 使用 `config/production.example.json` 执行相同构建入口，生成独立生产包。检查其中有 Python app/run.py、静态页面、扩展和 runtime 锁；没有 dummy、probe、lifecycle-test 产物、测试、模拟登录/控制页面、源码映射或开发依赖。
3. 此时已存在生产入口，执行 `bash .agent/run.sh python dist/production/run.py --config config/missing.local.json`，确认因缺配置失败，而非因入口文件不存在失败。
4. 使用 `config/production.example.json` 启动相同 Python 入口。该配置只使用保留域名，不访问真实外部系统；通过容器内 HTTP 客户端访问本地监听端口，Host/Origin 使用配置的看板来源，保持服务运行完成下列检查。
5. 核对 `test_production.py` 的隔离运行证据：从临时产物目录启动、只装 runtime 依赖且 PATH 无 Node/npm，页面/API/SSE 均工作。开发容器里一次成功启动不能单独证明这一点。
6. 请求 dummy 控制路径及 probe 页面，确认生产未注册；对共享 API 发送来源不匹配写请求、未知预览字段及伪造转发 IP，检查拒绝、脱敏错误与审计策略。
7. 确认共享服务为单 worker、同源提供页面/API/SSE，默认端口仅映射 loopback；持久化数据目录明确，重启后合成共享数据保留。完成 M10 后停止本地演练服务。

**预期：**dummy 便利功能不会进入生产，缺公司配置不会悄悄退回模拟成功。

**证据：**构建/配置负例和脱敏审计结果。测试中的虚拟代理只证明逻辑，不代表公司网络验证。

## M11：以后公司接入（P0，公司接入必需；本次不执行）

**前提：**实际工作台地址、Jira 9.7 地址/context path、Mattermost 服务器版本/地址、登录方式、两个不同权限的真实浏览器身份和内网部署条件。

**执行者：**有相应环境访问权限的用户；代理在可用能力范围协助。

1. 在本地非共享配置填写站点，不提供 Cookie/密码/Token给看板服务或代理。
2. 确认固定 GET 操作和最小权限，按正常浏览器登录流程读取；记录实际成功的请求上下文。
3. 验证 Jira 字段、分页及可见最新评论；MM 单消息、人员、频道和头像的字段访问。
4. 验证真实 SSO/会话过期、权限差异、模糊错误及跨站跳转；不主动制造真实限流。
5. 验证 HTTPS、内网/VPN边界、可信代理来源 IP 和生产包无 dummy 入口。

**预期：**逐项得出实测结论。不能复用会话时报告失败位置，另行讨论授权方案，不复制或集中保存凭据。

**证据：**环境版本、操作类别、是否通过和脱敏原因；不保存外部正文、认证信息或带正文的截图。
