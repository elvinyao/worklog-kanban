### 选型理由与取舍

- FastAPI/Pydantic 明确共享 API 的字段、校验与 OpenAPI；React 组件及 TS 状态类型组织看板、草稿、冲突和预览，适合本项目的交互复杂度。
- 原全 JavaScript 方案的主要优势是统一工具链；本次改为 Python + TypeScript，代价是两套依赖锁、分层测试及跨语言契约检查。以容器内统一入口和生成类型控制这些成本。
- SQLite 保留，改用 Python 标准库 sqlite3，删除 Node 数据库依赖。初版采用单实例、显式 SQL/事务，避免此阶段再增加 ORM、迁移框架或数据库服务。
- React 使用 Vite 构建为静态页面；不引入 SSR 服务、前端账号框架、全局状态库或 UI 组件库。核心样式与键盘/焦点行为按产品设计实现。
- pytest/HTTPX 验证 Python；Vitest 验证 TS 纯逻辑；Playwright 验证真实 React 页面、扩展和双身份。原 Node 内置测试方案由这三层替代。

## 3. Dummy 环境与数据边界

### 独立服务

| 服务 | 默认地址 | 范围 |
| --- | --- | --- |
| 看板 | `http://board.localhost:4173` | 共享 API、静态页面、事件流 |
| Jira dummy | `http://jira.localhost:4180/jira` | Jira 9.7 所需 REST 子集、模拟登录和原票据页 |
| Mattermost dummy | `http://mattermost.localhost:4181` | API v4 所需子集、模拟登录和原消息页 |

runner 的开发启动仅将这些端口映射到主机 `127.0.0.1`。浏览器必须实际检查三个地址可达；不自动修改主机 hosts。容器测试如需 DNS 映射，仅在测试浏览器中把这三个名称映射到 loopback，不关闭 CORS、Cookie 或其他浏览器安全检查。

Cookie 使用各服务自己的 host-only 范围，不设共同 Domain；看板服务不创建外部身份 Cookie。不同端口不能代替主机隔离。浏览器 A、B 使用独立 profile/context，在两个 dummy 的登录页分别选择模拟身份，预览请求不携带 `user=alice` 或身份选择头。

所有页面明确显示“模拟环境”。示例数据、诊断和截图均使用合成内容，不导入公司数据。

### 模拟数据与控制

- Alice、Bob 都能编辑同一共享看板；外部权限由 dummy 服务按自己的模拟会话判断。
- Jira：公开票据、Alice 专属票据、无担当者/无评论票据；公开票据至少 53 条可见性不同的评论，含“旧评论最近被编辑”和“最新评论仅 Alice 可见”。
- 评论接口保留 Jira 9.7 的 `startAt / maxResults / total / comments` 结构、字符串 `body`、`created / updated` 和作者字段。权限过滤先于分页；测试服务可将实际页大小限制得小于请求值。
- Mattermost：公开消息、Alice 专属消息、长文本、基本 Markdown、缺失人员字段、头像读取失败；只实现所需单条消息及人员/频道/头像读取。
- 合成故障覆盖 401、模糊 403/404、429、200 HTML 登录页、延迟、连接失败、重定向和畸形响应。
- 登录、退出、会话失效和故障切换使用 dummy 自身的 `/__dummy/` POST 控制接口。它们只由该服务的模拟控制页面或测试准备代码调用，不加入扩展读取白名单，不由共享服务代调。
- 控制接口要求精确来源/Host 和 JSON 请求，不用于真实系统，也不注册到生产启动模式。重置仅作用于本次测试的合成数据；不删除用户现有数据库。
- 模拟的个人 API 响应和头像响应声明 `Cache-Control: no-store`，不得利用 HTTP 缓存绕过模拟权限变化。

## 4. 实现契约

### 扩展与适配器

1. Manifest V3：只向配置的看板站点注入桥接脚本，host permissions 只覆盖已配置的 Jira / Mattermost 主机。默认不申请读取 Cookie 内容的权限。
2. 页面与桥接脚本通信检查精确 origin、顶层 frame、消息版本及 request ID；service worker 再验证 sender 的 origin、frame 和协议。拒绝多余字段、任意 URL、方法和请求头。
3. 外部操作仅为 `jira.preview`、`mattermost.preview`；协议还可有握手和取消。worker 按已校验标识构造固定 GET 请求。长连接断开时取消该页面的未完成请求，不在关页后继续翻页读取。
4. 首先验证 worker 中由浏览器携带会话的读取；若不成立，验证限定原系统标签页中的同源读取。后一种方式只在实际需要时添加对应权限，仍只接受固定操作。记录实际成功的上下文，不通过复制 Cookie、添加代理或放宽浏览器安全设置求成功。
5. 所有外部正文、人员/频道与头像读取使用 `cache: no-store`，不读写浏览器 HTTP 缓存；使用 `redirect: error` 阻止自动跟随跳转。无法分辨网络和重定向原因时返回一般读取失败；仅在明确 401 或已识别的登录响应时提示登录，不根据 HTML 内容类型独自推断认证状态。
6. Jira 路径：`/rest/api/2/issue/{key}` 仅读 summary/assignee/status；`/rest/api/2/issue/{key}/comment` 完整处理分页，按可见评论的 created 选最新，不能按 updated 或第一页推断。分页不推进、响应不完整或请求失败时不能报告“最新评论读取成功”。
7. Mattermost 路径：`/api/v4/posts/{id}` 及关联的 users/channels/头像 GET；不调用 thread、reply、attachment 或写接口。作者/频道字段不可读时局部降级，不推断隐藏信息。
8. 原始响应先投影成 UI 需要的字段，再送入页面；认证头、Cookie、完整错误页不进入预览 DTO。头像转为有类型与体积限制的 PNG/JPEG 内存资源；不使用远程任意图片 URL，不经共享服务器转存。
9. 所有预览状态只存在于当前页面内存。关联更换、请求返回乱序、清理和刷新使用资源 key 与本地 generation 检查，旧响应不能覆盖新关联。

### 共享数据、接口和同步

单个看板、单个 SQLite 数据库，不引入多租户。建议表：
- `board_meta`：全局递增 revision。
- `columns`：id、name、position。
- `cards`：id、共享 title、notes、column_id、position、version、可空 Jira 关联。
- `mattermost_links`：id、card_id、规范化链接/标识、共享说明、position。
- `audit_events`：操作时间、类型、资源标识、连接来源 IP、revision；不保存预览或凭据。

SQL 外键、事务和服务校验共同保护数据。默认六列仅在新数据库初始化时创建；重启不得重复初始化或覆盖已有数据。

| 接口 | 约定 |
| --- | --- |
| `GET /api/board` | 返回共享快照及 revision，不包含任何个人预览 |
| `GET /api/events` | SSE 仅发送 revision/共享资源变更标识，不发送预览 |
| `POST /api/cards` | 创建共享卡片，可无 Jira |
| `PATCH /api/cards/:id` | 修改标题、笔记和关联，携带 expectedVersion；旧版本返回 409 |
| `POST /api/cards/:id/move` | 目标列/插入位置 + expectedBoardRevision；移动与重排原子提交 |
| `POST /api/columns`、`PATCH /api/columns/:id` | 新增、重命名，结构修改带 expectedBoardRevision |
| `POST /api/columns/reorder` | 完整列 ID 顺序 + expectedBoardRevision |
| `DELETE /api/columns/:id` | 带目标列及 expectedBoardRevision；事务内迁移卡片并删除列，至少保留一列 |

所有成功写入在同一事务中更新必要版本、顺序与审计记录，提交后发事件。冲突不留下部分变更；无关卡片的内容编辑不因别的卡片编辑而失败。列迁移保持被迁移卡片原相对顺序并追加到目标列末尾。

先连接事件流并缓存更新提示，再读取共享快照；事件流每次建立都发当前 revision。只接受不旧于已应用状态的快照，取快照期间若收到更高 revision 则补拉；重连重新取全量，避免快照与订阅之间丢更新。

本地未保存笔记与共享快照分开保存。远端更新、重连和 409 都保留草稿及其基准版本；用户比较后明确重新提交，不自动用最新版本号重试旧草稿。乐观移动失败恢复布局，并恢复到仍存在的原卡片或邻近列焦点。

### Python / TypeScript 边界与部署方式

- 共享 API 的唯一结构来源是 `app/schemas.py` 与实际 FastAPI 路由，保留 JSON 的 camelCase 字段，通过 OpenAPI 生成 TS 类型。扩展消息/外部预览契约独立保存在 TS，不混进共享 API schema。
- Pydantic 请求模型使用严格字段校验与 `extra="forbid"`。校验错误只返回允许的错误码和字段位置，不回显输入值；应用日志禁止记录原始校验异常、请求正文及认证头。TS 类型不能替代服务端或扩展的运行时校验。
- 同步 sqlite3 工作单元在工作线程中完成，从建连接到提交/关闭都在同一线程；异步路由不直接执行阻塞 SQL。版本检查和写入使用显式事务；同一异步写锁覆盖从数据库工作单元到提交后通知的整个过程，工作线程不直接操作 SSE 订阅表。取消请求时也必须等待已开始的工作单元完成并处理提交后的通知，不能提前释放写锁造成顺序错乱。
- 初版共享服务固定一个 Uvicorn worker，SSE 订阅表仅在该进程。写操作完成事务后再广播 revision，断线/队列积压时关闭连接并让客户端重新同步；重启后的 revision 从数据库读取。未来多进程部署必须先增加跨进程通知方案，本轮不引入 Redis。
- React 通过稳定 ID 和分开的共享、草稿、预览状态管理 UI；不直接修改 DOM 来同步业务状态。Effect 订阅有对称清理，StrictMode 重挂载不能残留监听/长连接或造成业务写入；初版使用 React 内置状态机制，不新增全局状态框架。
- Vite 只用于编译/打包。验收和生产由 FastAPI 同源提供构建页面、`/api` 和 SSE，避免浏览器调用另一来源的共享 API；未知 API 路径不能误返回 SPA HTML。扩展仍访问两个独立外部来源。
- Python dummy 是独立应用/进程；生产包仅含共享应用、静态页面、独立扩展和运行依赖。开发/测试需要 Node，生产启动仅需 Python。

### 渲染、刷新与共享服务安全

- 标题、笔记、关联说明、Jira 字段按文本渲染；Mattermost 只允许段落、换行、强调、列表、引用、代码和安全链接，先关闭 Markdown 原始 HTML，再按 DOMPurify 白名单处理。禁用脚本、事件属性、嵌入、样式和正文中的远程图片。
- 新标签链接仅允许规范化的 http(s)，使用 noopener/noreferrer。受限 CSP，不加载 CDN 脚本或统计服务。
- 共享写请求校验精确 Origin、Host、JSON content type 和固定自定义请求头；不开放跨站写入，不使用 GET 改数据。请求体采用共享字段白名单，未知预览字段返回错误。
- 共享服务绝不调用外部 API。日志只写允许的操作元数据，不输出请求/响应正文及认证头。可信代理名单默认空，只有配置的代理可提供转发 IP。
- 页面预览并发上限 4，同页面同资源合并请求；可手动刷新，不周期轮询。429 遵循 Retry-After，在重试允许前禁用重复读取；不高频自动重试。
- 明确的登录失效或权限拒绝清除对应预览；网络失败保留已有内容但标旧并显示最后成功时间。元数据/头像错误局部降级。
- 收到新增关联时，只由本页面独立请求；关闭页面、移除关联或刷新替代请求时取消不再需要的读取。pagehide 清理预览和对象 URL，pageshow 恢复时重新读取；预览不写入 localStorage、IndexedDB、CacheStorage 或扩展存储。

## 5. 文件职责

## 7. 计划中的执行入口

所有入口由 T01 建立工具约定、再由对应任务实现；本次文档修订不执行这些命令。开发镜像同时包含 Python 和 Node，因此任何复合流程也始终留在同一个 Docker 入口内。

| 命令 | 作用/预期 |
| --- | --- |
| `bash .agent/run.sh python --version`、`bash .agent/run.sh node --version` | 应输出 Python 3.13.15 与 Node v24.21.0；记录镜像 digest |
| `bash .agent/run.sh python -m piptools compile --allow-unsafe --strip-extras --generate-hashes --output-file requirements/runtime.txt requirements/runtime.in` | T01 首次生成 Python runtime 锁 |
| `bash .agent/run.sh python -m piptools compile --allow-unsafe --strip-extras --generate-hashes --output-file requirements/dev.txt requirements/dev.in` | T01 生成受 runtime 锁约束的开发锁 |
| `bash .agent/run.sh python -m pip install --require-hashes -r requirements/dev.txt` | 按 Python 完整开发锁安装；生产只安装 runtime.txt |
| `bash .agent/run.sh python -m tools.sync_deps` | 同步 Python/Node 锁并记录安装指纹；锁变化后先执行此入口 |
| `bash .agent/run.sh npm ci` | 按 package-lock 安装 Node 开发依赖；T01 首次用精确版本安装生成锁 |
| `bash .agent/run.sh npm run typecheck` | TypeScript strict/noEmit 检查，含页面、扩展、测试与构建配置 |
| `bash .agent/run.sh npm run build:probe` | T04 起生成独立 React 验证页和 dummy 扩展 |
| `bash .agent/run.sh python -m tools.dev --probe` | T04 起启动两个 dummy 与验证页服务；退出清理子进程 |
| `bash .agent/run.sh npm run build:probe -- --mode lifecycle-test` | 构建 React 开发版本的独立生命周期测试页；完整页面在 T09 后使用 build 的同名参数 |
| `bash .agent/run.sh python -m tools.dev --probe --mode lifecycle-test` | 仅 dummy 使用隔离的生命周期测试产物；完整页面去掉 --probe，Playwright 按场景选入口 |
| `bash .agent/run.sh npm run build` | T09 起生成完整 React 页面和 dummy 扩展 |
| `bash .agent/run.sh python -m tools.dev` | T09 起启动共享 FastAPI 和两个 dummy；停止不清除数据库 |

| `bash .agent/run.sh python -m pytest tests/backend` | 后端契约、实际 HTTP、SQLite/SSE 与生产包验证，按当前已实现任务选文件 |
| `bash .agent/run.sh npm run test:unit` | Vitest 纯逻辑测试，不冒充 DOM/浏览器验证 |

| `bash .agent/run.sh git add <本任务的明确文件列表>` | 只 stage 任务文件，不使用 git add . |
| `bash .agent/run.sh git commit -m '<本任务说明>'` | 计划批准、任务验证或最终证据后的本地提交，不 push |

T01 中用于首次生成锁的 pip-tools 引导安装也必须在容器内，安装第 2 节指定的精确版本，随后将其完整依赖纳入 dev 锁。更换 Python 镜像或锁文件后重新核对容器依赖，不复用主机安装。
