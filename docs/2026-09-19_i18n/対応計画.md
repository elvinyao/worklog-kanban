# T16 中文、日语、英语界面

基线：`98a88b7`，main，工作区干净；用户直接要求三语言、浏览器自动选择和手动切换，按此授权实施。沿用 Docker runner、锁定运行时和本地提交，不新增依赖、不 push。着手前前端 69 项通过。

## 设计

- 集中、带类型的三语言文案表；覆盖看板、详情/列管理、错误/连接状态、预览占位、辅助标签、页面标题，以及模拟接入页和模拟登录控制台。中文沿用简体，外部内容保持原文。
- 先读取本 origin 的 `worklog.language`（仅 `zh`、`ja`、`en`），否则按 `navigator.languages` 顺序匹配主语言；无匹配用英语。菜单保留“跟随浏览器”。只持久化语言码，存储不可用时仍可在当前页切换。
- React provider 保留原组件树，渲染时翻译状态键和格式化日期，切换不重新取预览、不更改共享数据、不丢失草稿。同步同 origin 的其他标签页；自动模式响应浏览器语言变化。
- 系统初始列通过已有审计信息确认（没有创建/改名记录且名称为种子名称），API 添加可空 `defaultNameKey`；前端只翻译有该标记的列。用户新增/改名的列保持原文，不按位置或名称猜测用户文本。无需数据库 schema 迁移。
- 缺失作者用语言无关空值表示，UI 翻译“未知用户”；不将真实作者名当作翻译键。模拟错误 HTML 的协议识别标记保持稳定。
- 模拟登录各 origin 的语言设置相互独立；真实 Jira/Mattermost 页面和正文不由本应用翻译。终端运维消息不属于浏览器 UI。

## 实施和验收

1. 先定义语言解析/存储回退、默认列识别和浏览器切换负例；实现核心后接入所有页面文案。
2. 运行前端/后端相关回归、类型/契约/边界检查、普通与 StrictMode 浏览器回归；检查三种语言下布局、日期、弹窗和草稿保留。
3. 使用 `app update --local` 更新用户当前 Docker 环境，保留共享数据。记录结果并本地提交。
