# 公司环境接入检查单

当前仅有合成环境，Jira 目标为 DC / Server 9.7，Mattermost 实际版本未知。以下项目需有公司环境后执行；不要把“待确认”改为已验证。

| 项目 | 需要确认的内容 | 当前 |
| --- | --- | --- |
| 站点与网络 | 工作台 HTTPS origin、Jira/MM 基址及 context path、内网/VPN入口、代理地址 | 待确认 |
| 版本 | Jira 9.7 实际补丁版、Mattermost 版本及所需 API v4 行为 | 待实测 |
| 登录 | 公司 SSO、正常浏览器会话、过期/重新登录流程 | 待实测 |
| 扩展策略 | Chrome/Edge 支持版本、受管分发许可、三站点权限 | 待确认 |
| 测试身份 | 两个可见范围不同的用户，各自独立 profile | 待提供环境 |
| 运维 | Python 3.13 单实例、持久数据卷、备份恢复、日志保留 | 待确认 |

使用者在自己的浏览器登录，不把 Cookie、Token、密码复制到看板、服务配置、工单或证据中。

1. 依据运行说明创建本地 `company.local.json`，构建并检查生产包不含 dummy/probe；在获准的内网环境由运维启动单实例服务。此检查单不构成实际部署指令。
2. 在获准的两个浏览器 profile 安装同一生产扩展，确认页面握手来源、端口和 context path 匹配。检查实际 Chrome、Edge 的装载与输入法操作。
3. 正常登录 Jira 9.7 后读取跨页评论，确认 REST v2 字符串 body、担当者、状态，以及按创建时间选出的最新可见评论；两个用户的权限结果分别核对。
4. 正常登录 Mattermost 后读取一条消息及其人员、频道、头像元数据。确认无讨论串、附件或写操作请求；不可见用户/频道/头像的降级符合真实权限。
5. 正常登出、重新登录及权限改变后手动刷新，确认旧正文清除。真实 SSO 跳转若不能通过固定无重定向 GET 读取，应记录失败类别，另行讨论授权方案；不得复制会话或临时放宽任意来源。
6. 检查共享修改/冲突/SSE 重连和数据库重启。验证 HTTPS、SSE 代理缓冲/超时、Host/Origin、来源 IP 和仅内网/VPN可达。配置真实可信代理前确认其会覆盖伪造转发头。
7. 仅记录版本、操作类别、是否通过和脱敏原因；不要保留真实正文截图、HAR、身份状态导出、认证头或原始响应。用合成数据复现需要留证的问题，不在真实系统主动制造限流。

对应测试矩阵 L01–L03 和手动步骤 M11。需要额外认证方案、多副本部署或对外开放时，先单独评审设计范围。
