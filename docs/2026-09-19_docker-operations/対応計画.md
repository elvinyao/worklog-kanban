# 一键 Docker 运行方案

日期：2026-09-19；基线 `14c549f`，main，工作区干净。用户直接要求集成启动、更新、停止和删除，并明确选择更新时自动拉取 Git 最新代码。该请求授权本次局部运行方式改进；沿用既有数据边界与业务功能，不重复请求实施许可。

## 设计与执行

- `docker.sh start/update/stop/remove/status/logs` 提供短入口；macOS 四个 `.command` 文件只转发同一入口。全部实际项目执行仍经过 `.agent/run.sh`，主机脚本仅编排 Docker，不安装/运行 Python/Node/Git 项目命令。
- 默认集成当前 dummy 环境：Compose 启动看板、Jira、Mattermost 三个容器，固定三域名/端口，均只发布 loopback。镜像多阶段构建，Node 仅存在于构建阶段；运行镜像只安装 Python runtime 哈希锁。
- 看板 SQLite 放入本项目命名卷 `/data/board.sqlite3`。stop 保留容器；remove 删除容器/网络但保留卷；remove --purge-data --yes 显式删除本项目卷。不开全局 prune，不自动删除既有 `.tmp/worklog.sqlite3` 或开发依赖卷。
- update 在隔离工具容器中验证 Git 无未提交/未跟踪改动、有跟踪分支，再执行 fast-forward-only 更新；拒绝自动 stash/reset/覆盖。提供 `update --local` 只重建当前代码。拉取失败时不停止旧服务。
- 构建候选镜像并使用临时数据库预检；通过后替换服务，健康检查必须携带正确 Host。失败保留/恢复旧镜像和同一数据卷，不先 down 再构建。更新会短暂停机，不承诺未来数据库迁移自动回滚。
- 从运行镜像导出扩展到固定 `dist/extension-docker`，在容器内原子替换，保留旧目录；导出失败不能报更新成功。首次浏览器装载及更新后的浏览器扩展刷新仍由浏览器完成。
- Docker 管理动作在开发镜像构建/依赖指纹检查之前分流，因此停止/删除不需要 npm/pip 安装成功。操作锁防止同时更新/删除同一项目。

审阅补充：快进更新具体使用 `fetch` 与 `merge --ff-only --no-autostash --no-overwrite-ignore`，以免上游新增文件覆盖本地被忽略文件。回滚保存并使用最后健康的有效 Compose 配置，不只恢复镜像；默认运维动作也读取该快照。写入代码/导出/快照的容器辅助程序使用 checkout 所属 UID/GID，导出目录为 0755；兼容修复仅调整旧开发容器创建的 root 所有 `dist`、`.tmp` 父目录，不递归修改用户文件。操作锁优先使用已有应用镜像。提供 `--project NAME` 供测试数据隔离，端口仍固定。
