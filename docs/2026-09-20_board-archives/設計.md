# 首页预览开关与归档看板设计

本稿对应用户提出的首页密度、Board Archive、归档列表和交互设计。调研基线为 `31a167a`，分支 main，开始时工作区干净。本文是设计提案，不代表功能已经上线。正式行为、数据迁移和部署不在本轮设计演示中执行。

配套 [interaction.html](interaction.html) 是使用合成数据的可点击设计稿，覆盖开关、详情、归档确认、列表、重命名与恢复。为了便于比较卡片密度，演示使用三列工作流；正式功能仍保留用户已有全部列。设计稿没有接入真实 API，也未模拟所有异常、分页和翻译。

## 1. 目的与确认的现状

- 首页默认展开 Jira 和挂在其下的全部 Mattermost，容易让单卡过高。
- `App.tsx` 目前把整个 Current 的资源交给 PreviewProvider，单纯隐藏组件仍会读取源站。开关必须同时控制展示和资源订阅。
- 目前只有一个可编辑共享看板，SQLite v2 的 columns/cards 没有 boardId；列只有名称/排序，没有可靠的完成语义。defaultNameKey 是展示提示，不能当作业务状态。
- 现有共享数据包括标题、笔记、Jira 链接、Mattermost 链接/说明及层级关系；个人预览只在浏览器内存中。
- 列与卡片支持并发版本校验。归档需要延续这套保护，并保护其他用户正在编辑的草稿。

## 2. 归档范围的选择

| 方案 | Current 的变化 | 历史记录 | 适用情况 |
| --- | --- | --- | --- |
| A：归档选中的已完成任务（推荐） | 移走本次选中的已完成卡片，其他保留 | 一批完成任务及当时列结构 | 日常清理，最直接解决任务堆积 |
| B：整板快照，再移走选中的已完成任务 | 与 A 相同 | 当时所有任务，包含未完成任务 | 每周/每个迭代的完整回顾，会反复记录仍在做的任务 |
| C：整板归档，Current 清空 | 所有卡片移走，保留列结构 | 当时整个看板 | 整个项目阶段结束后重新开始 |

用户已明确选择 A：「归档已完成任务，保留未完成任务」。本稿和交互演示据此展开。B/C 仅保留为比较，不纳入首版，也不在实现时混用。

## 3. 首页预览开关

- 首页工具栏提供唯一的「卡片预览」开关，默认关闭。没有浏览器偏好时为关；用户切换后记住当前浏览器的选择，刷新保留。该布尔偏好不在共享服务保存，不影响其他人。
- 关闭时显示卡片标题、最多两行笔记摘要、Jira 数量与消息数量。没有关联时不显示数量标记。数量来自共享链接，绝不为显示摘要而读取外部内容。
- 开启时恢复已有淡绿色 Jira 分组框和其下所有 Mattermost 消息，继续三行摘要。开关旁显示开/关状态；键盘可操作且提供 switch 语义。
- 首页关闭不会禁止详情预览。点开一张卡片，仅订阅这张卡片的资源；关闭详情且首页仍关闭时取消请求并释放未使用的内容和头像。
- 首页开启时订阅当前正在查看的看板资源；详情与首页共享同一资源缓存，仍按资源去重。关闭首页预览时立即取消不再需要的请求，忽略迟到响应。限流冷却不能通过反复切换被绕过。
- 隐藏模式不占一整行显示扩展连接状态/刷新全部预览；相关控件在预览开启时或详情中出现。共享同步状态仍显示。
- Current 和归档详情共用同一浏览器偏好；归档列表永不加载个人预览。切换看板清理旧资源，页面离开、撤权、登录失效继续执行现有清理规则。
- 中文、English、日本語同时补齐。语言选择仍只有首页顶部一处。

## 4. 页面入口与归档列表

保持 Worklog 顶部品牌、语言切换和同步状态，下面增加「Current」「Archives · 数量」两个导航入口。Current 工具栏包含卡片预览开关、归档任务、列管理和新建任务。归档是次级按钮，避免与新建任务争夺视觉重点。

归档列表占完整内容区域，不放入层层下拉框，也不为每份归档展示卡片内容。默认按归档时间倒序，先取 20 条，底部「加载更多」。每行包含：

- 归档名称：主要点击入口，例如「2026-09-20 · 本周完成」。
- 可选说明：一行截断，详情可读完整说明。
- 归档日期和时间：按当前浏览器时区/界面语言格式化。
- 卡片数量、Jira 关联数量：Jira 数量按链接条目计数，跨卡重复票据不去重；文案明确为关联数。
- 「查看」和「重命名」操作。名称最长 80 字、说明最长 500 字，名称不要求唯一，内部 ID 区分。

顶部搜索按归档名称/说明匹配，服务端搜索后分页，不只过滤已加载的一页。首版不混入 Jira/源站正文全文检索，也不按未经保存的任务完成时间搜索。无结果时保留搜索框；无归档时提供「返回 Current 归档任务」。不显示虚构的归档人：当前系统没有登录用户身份。

移动端每行变为纵向排列，保留名称、日期、数量和明确操作按钮。导航使用可分享地址：`/`、`/#/archives`、`/#/archives/<id>`；返回列表保留搜索与已加载位置，浏览器前进/后退有效。

## 5. 创建归档的完整流程

1. 在列管理中把一个或多个列标记为「完成列」。原有可明确识别的系统默认 Done 列在升级时标记；改名后的自定义列不根据文本猜测。没有完成列时，归档入口引导设置，不自动选择最后一列。
2. 点击「归档任务」，打开一个确认对话框。无需先建空归档，也不直接执行移动。
3. 默认名称为本地日期加「已完成任务」，可以修改；可填说明。
4. 清单按完成列分组，默认勾选当前所有完成卡片，可取消勾选部分卡片。显示标题与 Jira 标识，绝不加载源站预览。未完成卡片不进入这个清单。
5. 对话框底部实时显示「将归档 8 项，Current 保留 12 项」。主按钮明确写「归档 8 项」；零选中时禁用。不再增加重复的二次确认框。
6. 提交期间禁用重复提交。成功后留在 Current，看板更新，提示「已归档 8 项」并提供「查看归档」。所有列及未选中卡片保留，列内顺序连续且相对顺序不变。
7. 网络失败保留名称、说明、选择；重试使用同一操作标识。另一人改动看板导致版本冲突时不归档任何卡片，刷新候选内容并要求重新核对，不静默接受变化后的集合。

“已完成”由 Worklog 的完成列决定，不由个人账号能否读取某张 Jira、Jira 的外部状态或列的翻译文本决定。

## 6. 打开归档与恢复任务

归档详情复用看板布局，显示归档名称、日期、当时任务数量和「只读归档」。提供返回列表、卡片预览开关和「恢复任务」。按归档时列顺序展示；空列默认折叠为紧凑占位，保留当时工作流结构。

归档里的卡片标题、笔记、关联结构和列布局不可编辑、拖拽、添加或删除。归档名称/说明可单独改，归档日期不变。Current 后续改列名、删列、编辑任务不会改动历史内容。

打开卡片可查看当时保存的共享内容。开启个人预览时显示「源站实时内容」，说明 Jira/Mattermost 不是归档时的历史快照；权限不足显示现有状态，不影响共享历史的阅读。

恢复流程：

1. 在归档详情点击「恢复任务」，勾选一项或多项，默认不选，避免误恢复整批。
2. 选择 Current 中的一个目标列，默认第一个非完成列；不存在时要求显式选择。卡片按归档顺序追加到列末尾。
3. 明确显示「将创建 N 张新卡片，归档记录保留」，按钮「恢复到 Current」。恢复是从历史复制出新的卡片，不会把旧历史改为可编辑，也不会覆盖现有卡片。
4. 成功后提供「查看 Current」，保留归档页面。该归档条目若已有对应的恢复副本仍在 Current，显示「已在 Current」并提供打开入口，再次选择时排除；不按标题或 Jira URL 判断相同任务。
5. 同一操作重试不产生重复副本。副本后来再次被归档后，允许从旧归档重新恢复，产生新的独立任务。

首版不提供永久删除归档、自动定时归档、整板覆盖恢复、多份可同时编辑的看板。它们不是解决本次积压问题的必需功能。

## 7. 数据边界与实现方向

采用「一个 Current + 独立不可变归档快照」模型；暂不把全部现有接口改造为任意 boardId。这满足读取历史看板的需求，降低对拖拽、列管理、层级关系和同步的影响。

### 归档数据

- `columns` 增加明确的 `is_done` 标志；输出模型增加 isDone。重命名不改变语义，新增列默认 false。
- 新增 `board_archives`：id、name、description、created_at UTC、source_revision、metadata_version、snapshot_schema_version、card_count、jira_link_count、共享内容快照。
- 快照使用独立严格模型：冻结的列 ID/名称/defaultNameKey/isDone/顺序，以及选中的完整共享卡片、原 ID/版本/位置、三级关联。只存共享字段，不接收浏览器拼装的源站内容。
- 新增操作记录，以 requestId 唯一约束保存归档/恢复的请求摘要和结果标识。相同 ID + 相同请求返回已有结果；相同 ID + 不同请求报冲突。
- 恢复来源记录 `archive_id + archived_card_id + restored_card_id`。活动副本按真实 Current 卡片是否存在判定，避免仅靠永久布尔值阻止未来恢复。并发恢复同一来源时最多创建一个活动副本。
- 归档表与 Current 同库备份。SQLite v2 → v3 自动备份、事务迁移，不能清空、重新播种或替换现有数据卷。

### 原子写入与同步

创建归档在一个写事务内：校验 expectedBoardRevision、选中 ID 唯一且非空/仍属完成列 → 从数据库读取并序列化共享快照 → 写入归档与操作记录 → 移走选中的 Current 卡片及其关联 → 整理剩余位置 → revision 增一并写最小审计。任一步失败全部回滚；不能先清理 Current 后异步保存历史。

恢复在一个写事务内：校验 Current revision、目标列、归档条目、无活动副本 → 创建新 card/Jira/message ID，保留共享内容及关联顺序 → 写来源映射/操作记录 → revision 增一并审计。恢复来源中的旧 URL 若不再符合部署配置，不静默丢链接或绕过校验；拒绝本次恢复并指出需检查站点配置，归档仍可读。

归档元信息重命名使用 metadataVersion。所有真实提交沿用单一全局 revision 通知，允许 Current 与列表更新，不在 SSE 携带快照或外部内容。现有 WriteCoordinator 每次都会发布 revision，需改为只为实际提交发布；幂等重试不发布旧 revision。幂等响应中的 Current 应为本次读取的最新版本，避免 UI 回退到历史状态。

### 候选接口

| 接口 | 用途与输入 |
| --- | --- |
| `GET /api/archives?q=&cursor=&limit=20` | 返回元信息摘要、总数及下一页游标；时间+ID稳定排序，不传每份完整快照 |
| `POST /api/archives` | requestId、expectedBoardRevision、name、description、cardIds；返回 archiveId 与当前最新 Current 快照 |
| `GET /api/archives/{id}` | 读取归档元信息、冻结快照和当前活动恢复映射 |
| `PATCH /api/archives/{id}` | name/description、expectedMetadataVersion；只改元信息 |
| `POST /api/archives/{id}/restore` | requestId、expectedBoardRevision、cardIds、targetColumnId；返回新卡片映射与 Current |
| `PATCH /api/columns/{id}` | 保留名称修改，增加显式 isDone 编辑；输入至少一项可编辑字段 |

所有接口继续使用现有同源与部署边界，能编辑 Current 的访问者可归档/恢复。不增加个人账号或新角色系统，不把审计 IP 当用户名。归档创建/恢复 ID 列表必须验证唯一性、存在性和请求大小；非法输入不能有部分成功。

### 编辑中的任务被别人归档

当前 App 在 snapshot 找不到卡片时会卸载 CardDialog。增加归档后必须保留已打开卡片的基准值和编辑草稿，提示「此任务已归档」，禁止覆盖保存，并提供查看归档和复制草稿。用户关闭前不得丢输入。后端旧编辑/移动请求返回明确 archived 冲突和归档标识，不自动创建卡片。导航离开有未保存草稿时继续已有草稿保护。

## 8. 影响范围与验证要求

候选修改：

- `src/web/App.tsx`：路由/视图选择、预览偏好、仅当前可见资源、已归档编辑态。
- `src/web/components/Board.tsx`：预览开关、只读模式、紧凑摘要。
- `src/web/components/PreviewProvider.tsx`、`src/web/state/preview.ts`：核对取消、资源释放和限流复用；优先复用已有 setResources 行为。
- `src/web/components/ColumnDialog.tsx`、`CardDialog.tsx`、新增归档列表/创建/详情/恢复组件：交互与草稿保护。
- `src/web/i18n/messages.ts`、`src/web/styles.css`：三语言与响应式。
- `app/schema.sql`、`store.py`、`schemas.py`、`api.py`、`events.py`、`errors.py`、`associations.py`：迁移、原子归档/恢复、同步、错误与共享关联序列化。归档职责集中于新的 `app/archives.py`，避免 store 持续膨胀。
- `src/web/api.ts`、生成的 API 类型：严格输入输出。
- 运行说明和验证证据：更新数据备份/回退方法，注明 v3 与旧镜像兼容边界。

无新增依赖，继续 Python/FastAPI + React/TypeScript。所有后续构建、测试和数据操作通过 `.agent/run.sh`。

必须验证的场景：

1. 初次打开预览关闭且外部读取为零；只开详情读取该卡；关闭取消与清理；偏好刷新持久化且不跨用户同步。
2. 开启后恢复 Jira/MM 分组，资源去重，三语言、键盘、窄屏、拖拽不回归。
3. 归档只移走勾选的完成卡，完整保留所有链接层级、历史游离消息、共享笔记和原排序；普通任务/空选择不误归档。
4. 老库备份和迁移成功，失败原子回滚；新增/改名/删除完成列行为明确。
5. 同时编辑/移动/归档，事务失败、断线重试、请求 ID 冲突和双人同时恢复，不丢数据、不重复副本、不回退 revision。
6. 已打开的草稿在其他人归档后仍保留，旧保存无法覆盖归档内容。
7. 列表跨页搜索、空态、只读详情、路由后退、重命名冲突、目标列被删/变更及恢复副本追踪。
8. 整个 Current、归档 API、数据库、日志中没有 Jira/MM 源站正文或头像；Alice/Bob 权限隔离和后台重连仍正确。

本轮只检查设计和交互演示，不运行产品回归或迁移；后续实现计划拆分为预览开关、数据与接口、归档界面、验收四个成果。归档范围已确认，详细交互设计在本稿中供用户审阅。
