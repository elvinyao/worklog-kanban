# Jira / Mattermost 共享工作看板：第一版设计

日期：2026-09-19

本文定义第一版范围，已完成设计审查。用户已指示进入实施计划，并于 2026-09-19 补充：暂无公司环境，先提供 dummy，目标 Jira 为 DC / Server 9.7。当前实施进度见 [结果 README](../../results/2026-09-19_worklog-kanban/README.md)。

## 1. 目标

提供一个独立的内网 Web 工作台，将团队的工作阶段、共享笔记、Jira 票据和 Mattermost 消息引用放在同一个看板内，减少页面切换。

共享工作数据与按个人身份读取的外部预览必须分离。任何成员读取到的 Jira 或 Mattermost 正文，都不能通过共享服务或协作广播自动提供给其他成员。

## 2. 已确认的产品范围

- 第一版仅部署于公司内网或 VPN 可访问的网络。
- 无账号、无成员角色；能够访问看板的人均可查看和编辑全部共享内容。
- 服务端记录操作时间与来源 IP。IP 是网络来源，不是可靠的个人身份。
- 第一版浏览器为 Chrome、Edge 等 Chromium 浏览器，允许安装限定站点权限的扩展。
- 目标 Jira 为公司自建 DC / Server 9.7；本轮先按其所需 REST 接口提供 dummy。
- Jira 和 Mattermost 均通过每个查看者自己的浏览器登录身份读取。
- 一张卡片可不绑定 Jira；绑定时最多对应一张 Jira 票据。
- 一张卡片可以关联多条 Mattermost 消息。
- 所有工作笔记均为团队共享，不提供私人笔记。
- 外部系统只读；看板操作不修改 Jira、不发送 Mattermost 消息。

## 3. 看板与卡片

默认列按以下顺序创建：待处理、调查中、实装中、单体测试、结合测试、完成。

团队可以新增、重命名、删除和重新排列列。删除有卡片的列时，必须指定另一个目标列并迁移卡片；没有其他列时阻止删除。保留至少一列。列表示本地工作阶段，与 Jira 正式状态相互独立。

卡片拥有独立的共享标题、所在列、排序、共享笔记、可选 Jira 链接以及有序的 Mattermost 消息链接。无 Jira 的卡片可用于会议、调查和临时工作，之后可以补绑或更换 Jira 链接。解绑只移除外部关联，不删除笔记和卡片。

Jira 要约作为个人预览展示，不自动保存为共享标题。手动写进标题、笔记或关联说明的内容均属于共享内容。

卡片正面保持紧凑，展示共享标题、可用的 Jira 概览和关联消息数量。详情区展示 Jira 评论摘录、各条 Mattermost 预览及共享笔记。第一版不默认展开完整外部正文或讨论串。

## 4. 数据归属

| 数据 | 存放与分发范围 |
| --- | --- |
| 列、列顺序、卡片位置、卡片顺序 | 共享数据库及共享协作更新 |
| 卡片标题、工作笔记、关联说明 | 共享数据库及共享协作更新 |
| Jira / Mattermost 关联链接及可由链接解析的标识 | 共享数据库，所有访问者可见 |
| 操作时间、操作类型、资源标识、来源 IP | 共享操作记录 |
| Jira 要约、担当者、状态、评论及人员信息 | 当前查看者浏览器内 |
| Mattermost 正文、作者、头像、频道信息 | 当前查看者浏览器内 |
| 外部登录 Cookie / 会话凭据 | 浏览器及原系统；不发给共享服务 |

关联链接本身是共享数据，即使某位查看者没有访问外部内容的权限，也可以看到和打开该链接。

第一版不将外部预览写入服务器、浏览器持久化数据库或协作事件，仅在当前页面生命周期内使用内存缓存。页面重新打开后重新获取。预览结果不得包含原始认证头或 Cookie，也不得写入应用日志。

## 5. 架构和请求流程

### 共享 Web 应用与服务

Web 页面提供看板、卡片详情、共享笔记、键盘交互和个人预览展示。共享服务保存共享数据、执行版本检查、发布共享变化事件并记录来源 IP。

共享服务不代替浏览器调用 Jira / Mattermost，不持有这些系统的用户凭据。

### Chromium 浏览器扩展

使用一套扩展适配 Chrome 和 Edge。扩展连接指定工作台及指定 Jira / Mattermost 站点。通过适当的浏览器请求上下文尝试复用当前会话；具体方式由公司环境连接验证决定，不预先承诺单纯跨域请求必然可用。

扩展只接受精确匹配的工作台来源。请求以固定操作类型和经过校验的票据或消息标识表达，由扩展构造允许的读取请求；不提供接受任意 URL、任意请求方法或任意请求头的代理接口。重定向不得将请求扩展到未允许的站点。

Jira、Mattermost 各自使用独立适配器，输出供 UI 使用的预览数据和规范化错误。只申请验证后实际需要的权限；如浏览器能自行携带会话，则不为读取 Cookie 内容而申请额外权限。

2026-09-20 追加：保留部署默认配置，并提供安装后的扩展设置页，允许修改工作台、Jira、Mattermost 地址。仅三个地址存于当前扩展 profile 的本地设置，不存预览和凭据；新主机需浏览器可选授权。页面与扩展需按三站点握手一致，切换配置或撤销扩展权限立即中止旧请求。详细边界见[扩展设置设计](../../2026-09-20_extension-settings/設計.md)。

### 打开看板

1. 页面从共享服务读取列、卡片、关联链接和笔记。
2. 页面连接本机扩展并检查站点配置。
3. 扩展使用当前浏览器的对应登录会话读取关联资源。
4. 页面展示个人预览及最近成功读取时间。
5. 共享修改通过服务同步；外部预览不进入该同步通道。

## 6. Jira 预览

展示票据编号、要约、担当者、正式状态，以及最新一条可见评论的作者、时间和正文摘录。无担当者或无评论时明确显示相应空状态。

“最新评论”指当前查看者有权限读取的评论中，创建时间最新的一条，不以编辑时间排序。读取逻辑必须处理评论分页，不直接假定票据响应内附带的评论就是全部评论。摘录展示两至三行，点击原链接在新标签页打开 Jira。

信息密度和视觉层次参考 Confluence 的 Jira macro，由本应用实现展示组件，不依赖嵌入 Confluence 宏。

## 7. Mattermost 预览

每个关联链接只读取和展示链接指向的那一条消息。展示作者头像、显示名字、发送时间、所属频道信息及正文摘录；仅展示当前身份能够读取的字段。

正文保留经过安全处理的基本格式，长内容截断。第一版不读取整条讨论串、不展开回复、不实现消息发送或附件查看器。点击 URL 在新标签页打开原始 Mattermost 消息地址。

远程头像等资源也属于个人预览，不经共享服务器转存。资源读取失败时使用占位图，不能使整个预览失败。

## 8. 加载、刷新与错误

打开看板时加载关联资源；提供手动刷新操作，不做定时轮询，也不在关闭看板后持续读取外部系统。同一页面内的重复资源请求合并，并限制并发请求数量，避免一次产生大量请求。

为共享内容同步、新增关联和个人预览刷新区分职责：共享事件只传链接和共享数据；收到新关联后，由当前查看者独立读取该新关联，不接收其他人的预览结果。

预览具有以下状态：加载中、读取成功、未安装或未连接扩展、需要登录、无权访问或资源不可用、网络错误、请求受限。仅当外部系统能够区分时才细分“无权限”与“不存在”，不能根据模糊错误推断资源存在。

登录失效或访问被拒绝时清除该资源现有预览，显示提示并保留原链接。临时网络失败时可以保留本页面已有内容，但明确标为旧内容并显示上次成功时间。收到限流响应时遵循服务返回的重试信息，不自动高频重试。

权限变化在下次请求时才能发现；不承诺实时撤销页面上已显示的内容。第一版不做持久化预览缓存，以缩小这一时间范围。

## 9. 多人协作与操作历史

共享修改成功后自动同步给其他已打开的页面。断线重连后重新拉取共享状态，以服务端状态为准。

卡片修改使用版本检查。两人同时编辑笔记时，后提交的旧版本不能静默覆盖新版本；保留该浏览器的未保存文本，并展示冲突，让用户比较最新内容后再保存。第一版不实现逐字协同编辑。

移动卡片和排序由服务端原子提交，确保卡片只属于一列、顺序有效；发生冲突时重新同步并提示，不留下部分变更。失败时还原乐观界面状态，并保留键盘焦点。

服务端使用连接来源记录 IP；部署于反向代理后，仅信任已配置的代理，不直接信任任意客户端提交的转发 IP 头。操作记录用于追踪来源，不宣称能识别个人，不记录外部预览正文或凭据。

## 10. 键盘与鼠标

| 操作 | 行为 |
| --- | --- |
| 上 / 下方向键 | 选择当前列上一张 / 下一张卡片 |
| 左 / 右方向键 | 选择相邻列的卡片，尽量保持相近序号 |
| Alt + 左 / 右方向键 | 移动选中卡片至相邻列末尾，并保持选中 |
| Enter | 打开选中卡片详情 |
| Esc | 关闭详情，焦点返回原卡片 |

最左或最右边界不循环。相邻列为空时可将焦点落到该列，不能误移动卡片。输入框和可编辑区域内的方向键、Enter 保持编辑用途；文本组合输入过程中不得触发看板快捷键。

详情关闭时若有未保存笔记，不静默丢弃，先提供继续编辑或放弃修改的选择。鼠标支持选择、打开详情、拖拽移动及排序，结果与键盘操作一致。

## 11. 接入验证与验收

根据用户补充，首个实施阶段在独立的 Jira 9.7 与 Mattermost API v4 dummy 服务上验证浏览器扩展的完整读取流程。使用两个模拟登录身份，权限由模拟服务判断，不用页面内硬编码数据替代扩展调用。Mattermost 的 v4 是 API 版本，不代表已知公司服务器版本。

本轮可继续完成共享看板、个人预览和交互的 dummy 验收，无需等待公司环境。以后进行真实接入时，仍需以下非敏感配置：工作台预期地址、Jira 地址与版本、Mattermost 地址与版本、两者登录方式。无需用户提供 Cookie、密码或 Token。

验证需要回答：当前浏览器会话能否读取票据指定字段和完整分页评论；能否按消息链接读取消息及显示所需的人员/频道信息；SSO 跳转和过期如何被识别；不同用户权限是否产生正确的不同结果。记录成功与失败条件，不将未验证路径作为已可用能力。

如果当前环境无法复用浏览器会话，应报告具体失败环节，重新讨论官方 API 授权等备选，不自动复制或集中保存凭据。

以下功能在本轮 dummy 环境验收；真实 SSO、公司权限及内网部署边界另列为待实测，不能以模拟通过代替：

- 两个浏览器使用不同外部身份访问同一看板，共享卡片与笔记一致，外部预览分别按个人权限展示。
- 无权限的查看者不会从共享 API、同步事件、日志或另一用户的预览缓存获得正文。
- 无扩展时仍可使用共享看板和原链接，预览显示明确的连接提示。
- 未绑定 Jira 的卡片可正常编辑、移动和关联消息。
- 六个默认阶段、列配置、鼠标拖拽和全部指定快捷键行为正确。
- 评论超过一页时仍能选出最新可见评论；Mattermost 不自动加载讨论串。
- 手动刷新、登录失效、网络错误和请求限流有可验证状态。
- 两人同时编辑笔记产生明确冲突，未保存文字不丢失；多人移动不破坏排序。
- 免账号访问限于部署网络边界，代理后的 IP 来源处理正确。

## 12. 开发约束与实施划分

2026-09-19 编写实施计划时，仓库已有本文和 CLAUDE.md，当前分支为 main；尚无应用代码、运行时声明、Docker runner 或测试。这是当时的基线，不表示已经搭建应用。

所有项目执行必须遵循用户提供的 Docker Execution Policy：先检查或创建 `.agent/run.sh`，再通过 `bash .agent/run.sh ...` 执行安装、构建、测试和项目工具。主机只用于检查及文件编辑。Docker 不可用时报告问题，不回退到主机执行。

后续实施按以下顺序细化为可独立验收的计划：

1. 模拟接入验证：独立 dummy、最小扩展与测试页面，验证两个模拟身份的会话读取和权限差异；为未来公司实测准备检查单。
2. 共享看板：数据模型、卡片和列操作、笔记冲突控制、操作历史及共享更新。
3. 预览接入：个人扩展桥接、Jira / Mattermost 适配器、预览组件与错误状态。
4. 交互和部署验收：键盘、拖拽、跨用户权限隔离及内网部署。

用户已确认按 Python/FastAPI 后端及 dummy、React/TypeScript 前端、TypeScript 浏览器扩展改写[实施计划](../../2026-09-19_worklog-kanban/対応計画.md)。具体版本、双运行时 Docker 入口、接口契约和分层测试以该计划为准；技术选择不代表已经安装或实现。第一阶段的结果是后续集成设计的依据。
