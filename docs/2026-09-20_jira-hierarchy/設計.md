# 预览恢复与 Jira 消息层级

用户明确要求修复“页面一直开着，几十秒到几分钟后预览消失”，并改为一张卡片关联多张 Jira、每张 Jira 关联多条 Mattermost。基线 `c7f2195`，main 干净；沿用既有授权直接实现，保留数据，不引入依赖。

## 预览恢复

已确认：任何 extension port 断开都会经 bridge → ExtensionClient → PreviewProvider 调用 PreviewStore.disconnect，清空成功内容且无自动恢复。Chrome MV3 后台闲置可在约 30 秒后停止，仅打开 port 不维持后台，因此与用户描述吻合。采用真实后台停止及 45 秒闲置浏览器用例验证，不将假设当自然闲置复现结果。

采用页面内缓存与有界重连。普通连接中断保留当前页面已成功内容和时间，暂停请求；以 0/1/3 秒退避重新 resolve 配置并 hello，握手成功后只重试中断/未完成的条目，不重读 ready 内容。失败耗尽清空并明确提示，页面离开取消所有恢复和缓存。后台主动设置变更/撤权通过明确 invalidation 通知立即清空；配置不一致、401/403/协议失败仍清空。不持久化预览，也不增加外部 API 定时轮询或通过外部读取保活。

候选：周期保活能减少休眠但不能覆盖后台终止/电脑休眠；简单保留所有断线内容不能区分撤权。选择显式安全失效与临时连接恢复的分离。

## 数据与编辑

`Card.jiraLinks[]` 的每项含 id/key/url/position 和自己的 `mattermostLinks[]`。输入只含 Jira URL/编号及消息 URL/说明；外部内容仍只由扩展提供。每卡最多 20 张 Jira，每票最多 20 条消息、整卡最多 100 条；Jira 规范化后不得在同卡重复。同消息可挂不同票，预览按资源去重。

新增 Jira 关联表，消息带同卡的 Jira 外键和组内次序。SQLite user_version 升到 2。升级前自动使用 SQLite backup 留存原库，迁移在单事务中完成，不修改卡片 ID、标题、笔记、版本、看板 revision、审计或消息 ID。

旧有 Jira 的卡片：票据成为首个 Jira，旧消息全部归其下。旧无 Jira 的消息：保留为 `unassignedMattermostLinks`，界面提供“待归属的历史消息”，可选已有 Jira 移入；新建界面只能在 Jira 下新增消息。遗留输入必须引用该卡已存在的遗留 ID 与原 URL，不能新造游离消息。删除票据的界面明确其下关联消息也随之移除；可先移动到其他票。0 张 Jira 的普通卡片仍可使用。

编辑继续以 expectedVersion 原子保存整卡，冲突保留整个层级草稿并展示当前共享层级。新 API 拒绝旧 jiraUrl/卡片级 mattermostLinks 写入，避免旧页面截断多票；升级后刷新页面。纯标题/笔记 PATCH 可继续使用。数据库保留旧 Jira 列但迁移后置空，不再作为真相来源；避免不必要的 cards 表重建。

列表显示多个 Jira 标识和预览，详情按 Jira 分组展示消息与预览。三语言同时更新。历史消息的保留是迁移兼容，不恢复新的卡片级消息功能。

### T22：首页分组预览

用户追加要求：首页卡片直接展示每张 Jira 及其下全部 Mattermost 消息。每张 Jira 使用细、淡绿色圆角边框作为共同容器，Jira 概览在上，按保存顺序排列的消息在下，消息间用更淡分隔线。不同 Jira 组留少量间距，避免消息归属混淆。消息使用小头像、作者/频道/时间及三行摘要，保留刷新、原文链接和访问状态；长内容在详情或原站查看。历史未归属消息继续通过现有标记和详情管理，不虚构父 Jira。

继续复用当前页面 PreviewStore 和 Preview，首页与详情不重复外部读取。只改前端显示与紧凑样式，无数据库、API、扩展协议或依赖变化。验证分组及全部关联消息、重复资源去重、个人权限、后台恢复、头像释放、窄屏和拖拽/键盘操作。此为用户已明确给出的局部布局调整，沿用直接实施与本地 Docker 交付。

桌面列最小宽度由 190px 调为 240px，防止新增作者/时间与摘要过度换行；空间不足继续使用既有横向滚动，移动端维持 250px 列宽。Markdown 摘要通过三行截断限制，避免固定高度与段落间距叠加造成半行裁切。

## 发布与验证边界

所有项目执行通过 Docker runner；先合成旧库验证迁移和回滚，再更新现有本地 Docker，保留共享数据卷及迁移备份。旧镜像不能读取 v2；镜像回退不能代替数据库恢复，记录备份路径和恢复步骤，不自动覆盖升级后的用户编辑。

验证普通/StrictMode 下闲置、后台停止、配置失效、撤权、登录失效、重连失败与页面离开；验证三级新增/排序/移动/移除、并发冲突、非法嵌套输入、三类旧卡迁移、重复启动、备份和失败原子性。公司 SSO 与实际受管浏览器仍沿用既有手动边界。
