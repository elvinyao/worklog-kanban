# 安装后的扩展站点设置

用户要求保留部署时配置，并增加安装后修改地址的设置页。本次授权覆盖该功能及必要的权限、连接和验证调整；沿用 main、inline 实现和本地 commit，不新增依赖。基线 `59ae95e`。

## 使用行为

- 从扩展图标或扩展管理页打开设置，编辑看板、Jira、Mattermost 三个地址；提供保存、恢复部署默认以及明确结果提示。沿用界面配色，按浏览器语言显示中文/英语/日语，不重复添加语言选择器。
- 未保存个人设置时使用构建配置。个人设置仅保存三个非敏感地址到该扩展的 `storage.local`，不同步到其他 profile，不存凭据或个人预览。自定义地址使用正式读取模式；恢复默认重新采用安装包的模式与地址。
- 一次启用一组站点。看板必须为 origin，Jira/MM 允许既有校验支持的 context path；拒绝用户信息、查询、片段、通配符及非法地址。
- 设置不修改服务器配置或共享卡片。看板 origin 不符则拒绝连接；在允许的看板中，页面与扩展在握手时核对三站点地址，不一致时明确提示且不调用外部 API。已有标签页在切换后清空旧预览；切换到新主机时刷新以注入脚本，同主机已有脚本可重新连接。未保存共享草稿不受影响。

## 实现选择

采用受控本地设置与动态 content script。仅维持构建配置不能满足要求；给所有网站直接授予访问权会扩大权限，因此不采用。manifest 保留三个部署默认站点的必需权限，以保持现有开箱连接；新增 HTTP/HTTPS 可选权限声明，仅在设置页的真实点击内请求具体主机。默认权限随安装包保留，自定义旧主机权限在成功切换后尽可能移除，运行时始终只接受当前精确地址。

扩展后台独占设置读写：设置消息仅接受本扩展设置页；content script 只能解析自己的当前配置。local 存储设为可信扩展上下文可访问。权限、注册和存储修改串行处理；失败保留旧配置，无法恢复则停止读取。损坏存储或权限丢失时不静默使用默认站点。

worker 在启动时恢复配置和动态注入，初始化完成前不读取外部系统。配置切换或权限撤销立即使旧 port 失效并取消请求，晚到结果不得返回。注销注入规则不能卸载已注入脚本，因此 worker 保持精确来源及会话代次校验。页面预期配置握手成功后才能读取资源；缺少地址的旧版握手返回配置不一致，需更新并刷新看板。权限清理仅考虑刚退役的配置，保留默认、当前及排队保存的主机，不全量清理其他设置页刚申请的权限。

动态脚本只注入当前看板主机顶层页面；进一步用精确 origin 验证端口。Jira/MM 请求仍由适配器按完整基址构造，固定 GET，禁止重定向。扩展选项不提供任意代理或认证内容输入。

## 交付和范围

设置资产包含于开发、Docker 导出和生产扩展。更新 Docker 导出白名单、生产包验证、三语言文案、使用说明和公司接入检查单。现有正式服务构建配置一致性及一键 Docker 的 dummy 范围保持不变；真实公司 SSO 和品牌浏览器受管安装仍需公司环境实测。
