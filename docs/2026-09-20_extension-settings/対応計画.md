# 扩展设置实施计划

目标：部署默认与安装后设置同时可用，切换不混用身份/站点/个人预览。

运行：沿用 Python 3.13.15 / Node 24.21.0 和锁文件；所有执行及 Git 写入经 `.agent/run.sh`。不新增依赖或 worktree，不 push。用户已明确要求增加本功能，按本设计实施；独立代理仅作只读审阅。当前进度统一记入既有项目结果 README。

## T19 配置、设置页和连接

1. 基线运行前端单元测试、构建、bridge/probe 浏览器用例。新测试先确认配置切换、权限拒绝/持久化失败、损坏配置与握手不一致尚不受支持。
2. 新增扩展设置契约与配置管理模块；实现默认/自定义、串行保存和恢复、权限核对、动态注册、失败回退与失效通知。用注入平台的逻辑测试验证状态转换，不模拟外部正文。
3. 修改 worker/bridge，初始化就绪后连接，配置切换及权限撤销取消旧请求；严格限制设置消息来源。扩展消息契约增加预期站点握手和明确不一致错误；页面/probe 显示该错误。
4. 新增 options.html/TS/CSS，复用既有语言核心，保存点击直接请求指定主机权限，恢复部署默认；按下保存到结果期间禁用并发点击，错误保持输入草稿。
5. 更新 manifest/build、Docker 导出和相应 Python 测试；三种产物均带完整设置资产。扩展图标打开设置页。
6. 使用真实 Chromium 扩展验证设置页、有效切换/恢复、不同端口和路径、旧预览清理、拒绝/失败、重启持久化和 profile 隔离；保留现有个人内容不持久化断言，仅允许站点配置白名单。
7. 完成相关单元、后端交付、完整普通浏览器及必要 StrictMode 回归，实际查看设置页窄屏与三语言布局。更新运行说明、设计边界和证据，独立只读审阅后本地提交。

验收观察点见同主题 `テスト観点マトリックス.md`。公司真实权限授权弹窗、SSO 和品牌浏览器策略不以容器模拟替代。
