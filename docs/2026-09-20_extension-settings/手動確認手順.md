# 扩展设置：原生浏览器验收

担当：使用者或公司浏览器管理员。使用真实 Chrome / Edge 与独立测试 profile；优先使用本地合成环境，不保存真实正文截图或认证数据。

## ES-M01 原生授权、保存、撤销与恢复（本地验收必需）

前提：Docker 看板已更新，加载新 `dist/extension-docker`；首次升级后重新加载扩展并刷新页面。新 profile 不应已有 `http://127.0.0.1/*` 的站点授权。

1. 点扩展图标打开设置，把看板地址暂改为 `http://127.0.0.1:4173`，其他两项不变，点击保存。应出现新增站点授权提示。
2. 拒绝。预期原配置保留；重开设置仍为 `http://board.localhost:4173`。
3. 再次保存并允许。预期提示已保存；重开设置和重启浏览器后仍为该地址。这里只验证配置保存，原默认看板不匹配时应停止预览，不将此看作真实网络连通成功。
4. 在浏览器扩展站点权限中移除该新增主机授权。预期设置页重新打开后显示需要权限；不能继续预览。重新保存后可再次授权。
5. 点恢复部署默认并刷新默认看板。预期恢复原三项地址；正常登录 dummy 后重新读取个人预览。共享卡片和编辑草稿不应被设置操作改写。

## ES-M02 实际第二套部署（公司接入时必需）

前提：已有获准的目标看板、Jira/MM 地址及同版本看板，不需要提供凭据给工具。

1. 用同一个扩展包填写与目标看板部署完全一致的三个地址，同意具体主机授权。
2. 打开目标看板，正常在目标原系统登录；验证 Jira 最新可见评论及 Mattermost 单条消息，确保来源链接指向新基址。
3. 在有加载中请求时撤销对应站点授权，预期旧内容清除、请求不再返回；重新授权并刷新后可恢复。
4. 用第二个独立 profile 重复，确认地址覆盖和个人会话互不影响。验证管理员策略禁止新主机时有可理解的失败提示，旧配置不被覆盖。

记录浏览器版本、各步骤是否符合预期及脱敏错误类型。原生弹窗点击、真实受管策略和公司 SSO 不由 headless Chromium 自动化代替。
