# Worklog Kanban 运行说明

这是使用 Jira DC / Server 9.7 和 Mattermost API v4 模拟服务的共享工作看板。后端为 Python / FastAPI，前端为 React / TypeScript。当前验证范围与缺项以 [结果 README](results/2026-09-19_worklog-kanban/README.md) 为准。

## 推荐：一键 Docker 运行

启动 Docker Desktop 或 OrbStack 后，在 macOS 双击仓库根目录的 `启动.command` 即可。首次会下载镜像和依赖，后续启动使用已经构建的版本。不需要主机 Python、Node、npm，也不需要先安装开发依赖。

跨平台 Bash 入口如下（Windows 可在 WSL 使用）：

```text
bash docker.sh start
bash docker.sh update
bash docker.sh stop
bash docker.sh remove
```

分别对应启动、更新、停止、删除；另有 `更新.command`、`停止.command`、`删除.command`。全部入口转到 `.agent/run.sh app ...`，项目代码、依赖安装、Git 更新均在容器中执行。运行镜像只含 Python 运行依赖；Node 只用于镜像构建。

启动完成后访问：

- [看板](http://board.localhost:4173/)
- [Jira 模拟登录](http://jira.localhost:4180/jira/__dummy/)
- [Mattermost 模拟登录](http://mattermost.localhost:4181/__dummy/)

三个服务后台运行，只发布本机 loopback 端口 4173、4180、4181；关闭启动窗口不会停止服务。若端口已被此前开发服务占用，先正常停止对应服务再重试。

在 Chrome / Edge 扩展管理页开启开发人员模式，首次“加载已解压的扩展”选择 **`dist/extension-docker`**。这个目录由启动自动导出；每次更新后点一次扩展“重新加载”，再刷新看板。浏览器权限安装无法由 Docker 自动完成。Jira/MM 分别登录 Alice 或 Bob 后才能读取个人预览；模拟登录会话在对应容器重启后失效，重新登录即可。

### 更新与失败恢复

默认 `update` 在容器中获取当前 Git 跟踪分支的代码并仅允许快进合并，然后构建候选镜像、用临时数据库预检，再替换服务。未提交或未跟踪改动、游离分支、没有 upstream、分叉、或上游文件将覆盖被忽略的本地文件，都会停止更新并保留现场；不自动 stash、reset 或覆盖。Git 的忽略文件保护使用 [`merge --no-overwrite-ignore`](https://git-scm.com/docs/git-merge)。

构建/拉取失败不停止原服务。替换后健康检查失败，会尝试恢复旧镜像及最后一次成功的 Compose 配置；成功配置保存在 `.tmp/docker-state/worklog-kanban/compose.json`。源码更新本身不会被回滚。替换会有短暂停机，此机制不代替数据库备份，也不保证未来不兼容数据库迁移的回滚。

只运行当前本地代码（例如保留未提交开发改动）时：

```text
bash docker.sh update --local
```

Git 工具容器不复制主机 SSH 密钥或凭据；私有仓库认证失败时旧服务保持运行。可先使用已授权的 Git 环境更新代码，再用 `--local` 重建。首次更新需下载 Git 工具镜像依赖。

### 数据与删除

共享数据保存在命名卷 **`worklog-kanban_board-data`** 的 `/data/board.sqlite3`，与代码、镜像和扩展分开。更新、停止、普通删除后重新启动都保留看板。此前开发模式的 `.tmp/worklog.sqlite3` 不会自动导入或删除；两种运行方式使用独立数据。

`stop` 保留容器；`remove` 删除本项目容器和网络，保留数据卷。需要连数据永久清空时才执行：

```text
bash docker.sh remove --purge-data --yes
```

这只删除本项目共享数据卷，不执行全局 Docker 清理，不删除源代码、其他项目、开发依赖卷或镜像缓存。删除语义与 [Compose down](https://docs.docker.com/reference/cli/docker/compose/down/) 一致。扩展旧目录保留为 `dist/extension-docker.previous-*`，确认无需回退后可自行清理。

### 状态与排错

```text
bash docker.sh status
bash docker.sh logs
```

服务通过 [Compose 健康等待](https://docs.docker.com/reference/cli/docker/compose/up/) 后才报告 `Ready`。日志窗口用 Ctrl+C 退出不会停止服务。相同项目的启动/更新/停止/删除会互斥；另一个操作仍在进行时等待其完成。若操作被强制杀死留下锁，先确认没有操作在运行，再在 Docker 管理界面删除名为 `worklog-kanban-operation-lock` 的**已创建但未运行**容器，随后重试。

测试或隔离数据时可用 `bash docker.sh --project NAME ACTION`；所有后续操作须使用同一个 NAME，数据卷会加对应前缀。端口仍固定，同一时间只运行一套。停止、删除和状态使用最后成功的配置，即使工作区的新配置有错仍可管理旧服务。

## 开发工具链（只在开发和测试时使用）

需要可用的 Docker（Docker Desktop 或 OrbStack）。所有项目命令从仓库根目录通过 `bash .agent/run.sh ...` 执行，禁止在主机直接安装或运行项目。

runner 构建包含 Python 3.13.15 与 Node 24.21.0 的开发镜像，挂载仓库为 `/workspace`。首次实际拉取后记录 `.agent/images.lock` 的镜像 digest；镜像变化使用独立的 Python/Node 依赖卷，不复用主机环境。虚拟环境位于容器的 `/opt/venv`，后续命令可继续使用已安装包。

首次 Python 锁文件生成：

```text
bash .agent/run.sh python -m pip install pip-tools==7.6.1
bash .agent/run.sh python -m piptools compile --allow-unsafe --strip-extras --generate-hashes --output-file requirements/runtime.txt requirements/runtime.in
bash .agent/run.sh python -m piptools compile --allow-unsafe --strip-extras --generate-hashes --output-file requirements/dev.txt requirements/dev.in
bash .agent/run.sh python -m pip install --require-hashes -r requirements/dev.txt
```

Node 首次安装由 T01 生成精确直接依赖与 package-lock。以后按锁安装：

```text
bash .agent/run.sh python -m tools.sync_deps
bash .agent/run.sh python -m tools.verify
bash .agent/run.sh npm run typecheck
```

`tools.sync_deps` 根据锁文件哈希运行 Python 锁同步与 npm ci，再记录依赖指纹；锁不变时跳过重复安装。入口会阻止普通项目命令使用旧锁对应的环境，直接安装/生成锁的命令仍可用于恢复。Docker 不可用时处理 Docker，不回退到主机执行。

TypeScript 源码保留 strict、exactOptionalPropertyTypes 和 noUncheckedIndexedAccess；skipLibCheck 仅跳过第三方声明内部检查，应用源码仍进行严格类型检查。当前 Vitest 锁定为 4.1.11。

## 模拟接入页与扩展

```text
bash .agent/run.sh npm run build:probe
bash .agent/run.sh python -m tools.dev --probe
```

启动后仅映射主机 loopback 的 4173/4180/4181 端口；终止开发命令会清理三个子服务，不修改 hosts。访问：

- 看板接入页：`http://board.localhost:4173/probe/`（仅 probe 启动时根地址自动跳转）
- Jira 模拟登录：`http://jira.localhost:4180/jira/__dummy/`
- Mattermost 模拟登录：`http://mattermost.localhost:4181/__dummy/`

在 Chrome / Edge 的扩展管理页面启用开发人员模式，选择“加载已解压的扩展”，加载仓库内 `dist/extension-dummy`。刷新接入页应显示“已连接”。在两个模拟登录页各选一次身份，再回到接入页读取。用独立浏览器 profile 验证 Alice/Bob；普通标签页共享同一个 profile 的身份。

扩展没有 Cookie 读取权限，由浏览器随固定 GET 携带会话。扩展 host 权限只能按 scheme/hostname 表示，代码进一步限制精确端口、路径、顶层 sender 和固定操作。请求不允许重定向；预览仅在当前页内存，不存入共享服务。Chromium 自动测试使用实际扩展和独立 profile；不能替代用户安装的 Chrome/Edge 或公司 SSO 验收。

自动化入口：

```text
bash .agent/run.sh npm exec -- playwright install chromium
bash .agent/run.sh env WORKLOG_TEST_PAGE=probe npm run test:e2e -- tests/e2e/bridge.spec.ts
```

开发镜像包含 Chromium 所需系统库和中文字体；浏览器二进制保存在专用 Docker 卷。测试仅在其浏览器内将三个 `.localhost` 名称映射到 loopback，不关闭浏览器安全检查，不保存 HAR、身份状态或页面正文日志。

生命周期测试使用独立 React 开发构建：

```text
bash .agent/run.sh npm run build:probe -- --mode lifecycle-test
bash .agent/run.sh python -m tools.dev --probe --mode lifecycle-test
```

普通 probe 和 lifecycle 产物分开保存在 `dist/probe` / `dist/lifecycle/probe`。测试 lifecycle probe 时同时设置 `WORKLOG_TEST_PAGE=probe WORKLOG_TEST_MODE=lifecycle-test`。

## 完整共享看板

```text
bash .agent/run.sh npm run build
bash .agent/run.sh python -m tools.dev
```

访问 `http://board.localhost:4173/` 使用完整看板；`/probe/` 保留接入验证页。默认初始化六列。无需扩展即可创建卡片、编辑共享纯文本笔记、绑定或解绑 Jira、排列消息关联，以及管理列。删除列需选择接收卡片的列，迁移和删除一起生效。

安装扩展并在两个 dummy 站点模拟登录后，看板自动读取已关联资源；卡片显示个人 Jira 概览，详情显示最新评论与单条消息摘录。工具栏可刷新全部预览，每个资源也可单独刷新。同资源合并读取、最多并发 4 个；没有定时外部轮询。登录失效或不可用时清除正文，网络失败保留带“旧内容”标记的本页结果，限流冷却结束后需手动再刷新。

预览仅保留在当前页面内存，离开页面会清除并取消请求，恢复页面后重新读取。个人预览不会自动写入共享标题或笔记。直接填写在共享字段的内容对所有看板使用者可见。Mattermost 保留安全的基本 Markdown，图片不自动加载，头像仅使用有界的内存 Blob；原文链接始终可打开。

共享数据库位于 `.tmp/worklog.sqlite3`，停止或重新启动不会清除。一个数据库只能由一个服务进程使用。不要删除数据文件来解决启动错误。自动化测试使用容器临时目录中的独立数据库，不使用此开发数据库。

多人编辑时，远端更新不会覆盖本地草稿；版本冲突会保留输入，显示当前共享内容，再由使用者选择“比较后用草稿保存”。关闭未保存的卡片有提示。页面断线后重新连接并补拉全量共享数据。

```text
bash .agent/run.sh npm run check
bash .agent/run.sh npm run test:unit
bash .agent/run.sh npm run test:e2e
bash .agent/run.sh npm run build -- --mode lifecycle-test
bash .agent/run.sh env WORKLOG_TEST_MODE=lifecycle-test npm run test:e2e
```

完整构建分别输出 `dist/web` / `dist/lifecycle/web`，并构建对应 probe。普通产物和 React 开发版本的生命周期测试产物分别验证。API 类型来自后端真实 OpenAPI：`npm run generate:api` 更新，`npm run generate:api:check` 检查漂移。以上命令都需使用同一个 Docker runner。

## 界面语言

支持简体中文、English、日本語。首次打开按浏览器语言偏好顺序选择；如日语浏览器显示日语，英语地区变体显示英语，中文地区变体显示简体中文。没有匹配时使用英语。

仅首页右上角提供语言按钮组：**自动 / 中文 / EN / 日本語**，当前选项高亮。卡片详情、列管理和接入验证页不重复放置入口。手动选择保留到下次访问，并同步同一浏览器内同站点的其他标签页；选择“自动”会取消手动偏好，恢复跟随浏览器。按钮支持 Tab 导航、Enter 或空格选择。浏览器禁止本地存储时，当前页面仍可切换。

界面、日期显示和未改名的默认列随语言变化；卡片标题、笔记、自定义列名、Jira/MM 原文保持原样。切换不会保存或丢弃草稿，也不会重新读取个人预览。仅语言码写入本地设置 `worklog.language`，个人预览仍只在内存中。接入验证页继承首页选择；独立 Jira/Mattermost 模拟站点仅按浏览器语言自动显示，不提供额外切换入口。

## 卡片操作

上下键选择同列卡片，左右键选择邻列卡片；空列可以获得焦点，边界不循环。Alt+左右将当前卡片移至邻列末尾。Enter 打开详情，Esc 关闭；未保存时先选择继续编辑或放弃。方向键和 Enter 在输入区域保持正常编辑用途。

鼠标拖到另一张卡片的上半部/下半部可插入其前后，拖到列空白处会移至末尾。移动冲突会回滚布局并保留焦点，需根据当前状态再操作。实际 OS 输入法、Chrome/Edge 安装验收情况见结果 README。

## 独立生产包

开发与构建需要 Python 和 Node；构建完成后的服务只需要 Python 3.13（本项目验证 3.13.15），无需 Node/npm。运行平台为支持 `fcntl` 文件锁的 Linux/macOS；本仓库在 Linux Docker 中验证，Windows 使用 Linux 容器。

1. 在 `config/company.local.json` 填入公开站点地址，字段与 `config/production.example.json` 一致，mode 必须是 production。配置不放密码、Cookie 或 Token，`*.local.json` 已忽略。工作台必须部署在域名根路径；Jira/MM 可带配置中明确的 context path。
2. 用该配置构建，前端、扩展部署默认值和服务采用同一组地址。服务器地址变更仍需重新构建并部署看板；已安装的本版本扩展可在设置页切换地址，无需仅为地址变化重新打包扩展。

```text
bash .agent/run.sh npm run build:production -- --config config/company.local.json
```

仅做离线交付演练时可使用保留域名示例：

```text
bash .agent/run.sh npm run build:production -- --config config/production.example.json
bash .agent/run.sh python dist/production/run.py --config config/production.example.json --database data/production-rehearsal.sqlite3
```

示例域名不会解析为真实公司站点；自动验收仅通过 loopback、设置示例 Host/Origin 访问本地服务，不访问外部系统。第二条演练命令使用既有开发容器的 Python，纯 runtime 环境的证明由 `test_production.py` 单独完成。

产物 `dist/production/` 包含 `run.py`、`app/`、`web/`、`extension/`、`requirements/runtime.txt` 和 `site-config.json`。没有 Node 依赖、dummy、probe、测试、开发构建、源码映射或模拟登录控制台。配置缺失、dummy 模式、与构建不一致、页面引用的静态文件缺失均失败，不回退到模拟环境。构建使用开始时的配置快照；成功后才替换旧产物，并将旧目录保留为 `dist/production.previous-<标识>`。旧版本需由维护者确认备份和内容后另行清理；不要在活动服务运行期间替换交付目录。

运维将整个生产目录交付给目标 Linux 容器/运行环境；在该环境创建 Python 3.13 虚拟环境，以 `python -m pip install --require-hashes -r requirements/runtime.txt` 安装运行锁，使用 `python run.py --config /config/company.json --database /data/board.sqlite3` 启动。以上是目标容器内操作说明；在本仓库操作仍必须通过 `.agent/run.sh`，不可在开发主机直接运行。

默认监听容器的 `0.0.0.0:4173`，仓库 runner 只发布主机 `127.0.0.1:4173`。实际部署必须由内网/VPN和反向代理限制访问，并在代理终止 HTTPS。保留原始 Host，允许 SSE 长连接、关闭 SSE 缓冲，按实际活跃时长配置超时。本版本没有看板账户/登录，能访问看板的人都可读写共享数据；个人 Jira/MM 权限仍由各自浏览器会话决定。不要将共享服务直接开放到公网。

生产扩展位于 `dist/production/extension`，按公司允许的受管扩展分发方式安装，或在获准的开发人员模式下加载目录。每个浏览器 profile 分别安装并登录原系统；服务端不代替浏览器登录。

## 扩展连接设置

两种配置方式同时支持：构建配置提供安装包的默认值，扩展设置页提供当前浏览器的覆盖值。首次升级到带设置页的版本时，在扩展管理页重新加载 `dist/extension-docker`（正式包为 `dist/production/extension`），并刷新已更新的看板。扩展包包含 `manifest.json`、`worker.js`、`bridge.js`、`options.html`、`options.js`、`options.css` 六个文件。

1. 点击工具栏中的 Worklog 扩展图标，或在扩展管理页选择其“扩展选项”。
2. 填写看板地址（例如 `https://board.example.com`，只填站点 origin，允许端口）、Jira 地址（例如 `https://jira.example.com/jira`）及 Mattermost 地址（例如 `https://chat.example.com`）。Jira/MM 可以带部署路径。不要填写某条 ticket/post 链接、密码、查询参数或 Token。
3. 点击“保存设置”。新主机会弹出浏览器站点授权提示，同意后才保存；拒绝时保留原设置。已经授权的站点通常不会再次询问。设置页显示中文、英语或日语，跟随浏览器语言。
4. 刷新看板；首次切换到新主机时，已打开的目标标签页必须刷新才能注入连接脚本。同一个看板且脚本仍在时，也可点“重新连接”。在目标 Jira/MM 中正常登录，然后刷新预览。设置切换会清除旧预览并取消旧请求，共享编辑草稿保留。
5. “恢复部署默认”删除当前浏览器的覆盖值，重新采用安装包内的配置；以后升级包也保留已有个人覆盖值，需手动恢复才采用新默认值。

设置页**不会修改看板服务器**。三项地址必须与目标看板部署完全匹配：看板 origin 不匹配时不能连接；同一看板的 Jira/MM 地址不匹配时提示“扩展地址与看板不一致”，两者均停止外部读取。旧版本看板未携带地址的握手也会被拒绝，需要更新并刷新页面。保存成功表示地址和授权已经保存，不代表已验证公司网络或 SSO 登录成功。

仅三个地址保存在扩展本地存储 `worklog.sites`，不跨浏览器 profile 同步。正文、头像、Cookie、密码和 Token 不会写入该设置。扩展不申请 Cookie 读取权限；Chrome 的站点授权按主机控制，代码进一步校验精确端口和路径。安装包的默认站点权限保留；切换后尝试释放旧自定义主机权限，并保护排队中的保存。多个设置页同时申请权限时，若权限被撤销，可重新保存完成授权。

若浏览器撤销权限或公司策略禁止可选主机，预览停止，共享编辑仍可使用。重新打开设置并保存可再次申请。配置损坏时显示错误，使用“恢复部署默认”修复；不要把删除共享数据库作为排错步骤。真实 Chrome/Edge 原生授权弹窗、受管策略和公司 SSO 需按[设置手动验收](2026-09-20_extension-settings/手動確認手順.md)验证。

## 数据、代理与停止

- 默认共享数据库为当前工作目录下的 `data/board.sqlite3`；建议部署时显式给绝对路径，持久挂载在生产目录之外。启动会拒绝位于生产目录内的数据库路径，也检查符号链接解析后的路径。在产物目录内启动时必须用 `--database` 指向目录外。
- 单 worker、单实例。不能多进程/多容器同时服务同一数据库，也不支持多副本各持一份数据库。`WEB_CONCURRENCY`/`UVICORN_WORKERS` 非 1 会拒绝启动，文件锁拒绝第二个实例。
- Ctrl+C 或 SIGTERM 正常停止；启动不清空数据库。备份前正常停止服务，备份数据库及仍存在的 `-wal` / `-shm` 配套文件。恢复到同一应用版本后再启动。先保留原文件，不用删除数据库来排障。
- 审计与日志只记录操作、版本、时间和来源 IP 等约定元数据，不记录标题、笔记、外部正文或认证头。默认忽略 X-Forwarded-For。仅实际代理连接地址可用 `--trusted-proxy IP/CIDR` 指定，多个可重复；禁止为方便而信任所有网络。代理必须覆盖客户端伪造的转发头。
- 生产无交互式 API 文档；`/health`、页面/API/SSE 需匹配配置的 Host，使用错误 Host 的探针会得到 403。

## 常见问题

| 现象 | 处理 |
| --- | --- |
| Docker 不可用或没有权限 | 启动 Docker/OrbStack 并恢复 runner 访问，不转到主机执行 |
| 端口占用 | 停止此前的演练服务；不要结束未知用户进程 |
| 扩展未连接 | 核对加载目录、站点及端口，刷新页面或点重新连接；共享编辑可继续 |
| 扩展地址与看板不一致 | 对照看板部署配置修改扩展三个地址，更新旧看板并刷新；设置页不能修改服务器 |
| 扩展设置提示需要站点权限 | 保存并同意浏览器授权；若被公司策略拦截，由管理员确认允许的站点 |
| 需要登录原系统 | 在对应 dummy 页或真实系统正常登录，再手动刷新预览 |
| 无权访问或资源不可用 | 在原系统确认权限；404 不表示资源一定存在 |
| 旧内容 / 请求受限 | 旧内容来自本页最后成功读取；等待提示时间后手动刷新 |
| 生产启动被拒绝 | 核对生产配置与构建一致、静态文件完整、合法代理网段及单 worker 设置 |
| 数据库已被实例占用 | 正常停止此前实例后重试；不要删除锁/数据库绕过活动实例 |

接入真实系统前执行 [公司接入检查单](公司接入检查单.md)。Dummy 通过不能证明真实 SSO、权限和部署网络已通过。
