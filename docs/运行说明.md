# Worklog Kanban 运行说明

当前实现状态以 [结果 README](results/2026-09-19_worklog-kanban/README.md) 为准。完整看板与生产交付步骤随对应任务补齐。

## 工具链

需要可用的 Docker（Docker Desktop 或 OrbStack）。所有项目命令从仓库根目录通过 `bash .agent/run.sh ...` 执行，禁止在主机直接安装或运行项目。

runner 构建包含 Python 3.13.15 与 Node 24.21.0 的开发镜像，挂载仓库为 `/workspace`。首次实际拉取后记录 `.agent/images.lock` 的镜像 digest；镜像变化使用独立的 Python/Node 依赖卷，不复用主机环境。虚拟环境位于容器的 `/opt/venv`，后续命令可继续使用已安装包。

首次 Python 锁文件生成：

```text
bash .agent/run.sh python -m pip install pip-tools==7.6.1
bash .agent/run.sh python -m piptools compile --allow-unsafe --strip-extras --generate-hashes --output-file requirements/runtime.txt requirements/runtime.in
bash .agent/run.sh python -m piptools compile --allow-unsafe --strip-extras --generate-hashes --output-file requirements/dev.txt requirements/dev.in
bash .agent/run.sh python -m pip install --require-hashes -r requirements/dev.txt
```

Node 首次安装由 T01 生成精确直接依赖与 package-lock。以后按锁安装：

```text
bash .agent/run.sh python -m tools.sync_deps
bash .agent/run.sh python -m tools.verify
bash .agent/run.sh npm run typecheck
```

`tools.sync_deps` 根据锁文件哈希运行 Python 锁同步与 npm ci，再记录依赖指纹；锁不变时跳过重复安装。入口会阻止普通项目命令使用旧锁对应的环境，直接安装/生成锁的命令仍可用于恢复。Docker 不可用时处理 Docker，不回退到主机执行。

TypeScript 源码保留 strict、exactOptionalPropertyTypes 和 noUncheckedIndexedAccess；skipLibCheck 仅跳过第三方声明内部检查。Vitest 4.1.0 的声明在 exactOptionalPropertyTypes 下自身不兼容，应用源码仍进行严格类型检查。

## 模拟接入页与扩展

```text
bash .agent/run.sh npm run build:probe
bash .agent/run.sh python -m tools.dev --probe
```

启动后仅映射主机 loopback 的 4173/4180/4181 端口；终止开发命令会清理三个子服务，不修改 hosts。访问：

- 看板接入页：`http://board.localhost:4173/probe/`（仅 probe 启动时根地址自动跳转）
- Jira 模拟登录：`http://jira.localhost:4180/jira/__dummy/`
- Mattermost 模拟登录：`http://mattermost.localhost:4181/__dummy/`

在 Chrome / Edge 的扩展管理页面启用开发人员模式，选择“加载已解压的扩展”，加载仓库内 `dist/extension-dummy`。刷新接入页应显示“已连接”。在两个模拟登录页各选一次身份，再回到接入页读取。用独立浏览器 profile 验证 Alice/Bob；普通标签页共享同一个 profile 的身份。

扩展没有 Cookie 读取权限，由浏览器随固定 GET 携带会话。扩展 host 权限只能按 scheme/hostname 表示，代码进一步限制精确端口、路径、顶层 sender 和固定操作。请求不允许重定向；预览仅在当前页内存，不存入共享服务。Chromium 自动测试使用实际扩展和独立 profile；不能替代用户安装的 Chrome/Edge 或公司 SSO 验收。

自动化入口：

```text
bash .agent/run.sh npm exec -- playwright install chromium
bash .agent/run.sh env WORKLOG_TEST_PAGE=probe npm run test:e2e -- tests/e2e/bridge.spec.ts
```

开发镜像包含 Chromium 所需系统库和中文字体；浏览器二进制保存在专用 Docker 卷。测试仅在其浏览器内将三个 `.localhost` 名称映射到 loopback，不关闭浏览器安全检查，不保存 HAR、身份状态或页面正文日志。

生命周期测试使用独立 React 开发构建：

```text
bash .agent/run.sh npm run build:probe -- --mode lifecycle-test
bash .agent/run.sh python -m tools.dev --probe --mode lifecycle-test
```

普通 probe 和 lifecycle 产物分开保存在 `dist/probe` / `dist/lifecycle/probe`。测试 lifecycle probe 时同时设置 `WORKLOG_TEST_PAGE=probe WORKLOG_TEST_MODE=lifecycle-test`。

## 完整共享看板

```text
bash .agent/run.sh npm run build
bash .agent/run.sh python -m tools.dev
```

访问 `http://board.localhost:4173/` 使用完整看板；`/probe/` 保留接入验证页。默认初始化六列。无需扩展即可创建卡片、编辑共享纯文本笔记、绑定或解绑 Jira、排列消息关联，以及管理列。删除列需选择接收卡片的列，迁移和删除一起生效。个人预览的实现进度见结果 README。

共享数据库位于 `.tmp/worklog.sqlite3`，停止或重新启动不会清除。一个数据库只能由一个服务进程使用。不要删除数据文件来解决启动错误。自动化测试使用容器临时目录中的独立数据库，不使用此开发数据库。

多人编辑时，远端更新不会覆盖本地草稿；版本冲突会保留输入，显示当前共享内容，再由使用者选择“比较后用草稿保存”。关闭未保存的卡片有提示。页面断线后重新连接并补拉全量共享数据。

```text
bash .agent/run.sh npm run check
bash .agent/run.sh npm run test:unit
bash .agent/run.sh npm run test:e2e
bash .agent/run.sh npm run build -- --mode lifecycle-test
bash .agent/run.sh env WORKLOG_TEST_MODE=lifecycle-test npm run test:e2e
```

完整构建分别输出 `dist/web` / `dist/lifecycle/web`，并构建对应 probe。普通产物和 React 开发版本的生命周期测试产物分别验证。API 类型来自后端真实 OpenAPI：`npm run generate:api` 更新，`npm run generate:api:check` 检查漂移。以上命令都需使用同一个 Docker runner。生产独立交付入口在 T13 补齐。
